# Registered private business consumer composition

`NewRegisteredClientSet(product, clients, revalidators)` is a server-only composition over the existing Client and confidential Revalidator. Each client is created with its exact approved product/client/application/platform/origin/callback/bundle/package/scopes; the corresponding reader is `NewPrivateBusinessRevalidator` with that platform's separately registered public key and protected private-key file. This API does not install or generate credentials, enable a product, or accept a client supplied policy. Cloud Native and Merchant Native remain unregistered/rejected.

The original nineteen-field device proof has no platform field. Selection matches the entire original registered signed tuple against exactly one configured client. The subsequent gateway authorization verifies its original proof, scopes and actual response platform. A response cannot select another reader or widen permissions. Unsupported/ambiguous tuples reject before gateway transport. Web requests still require their own original Central browser actor/cookie/CSRF check; Native requires the verified account/device binding and actual registered Native enrollment, not a browser cookie fabricated by a Native caller.

Use the following sequence at the real product route:

1. Select required scopes from the fixed server route and call `set.Authorize(ctx, request, scopes)` once. Preserve the full returned `productsessionv2.Session` privately in request/operation context. Do not reconstruct it from the reduced business DTO, and do not replay its consumed introspection proof.
2. Pass the separate existing business proof header, unchanged method/path and raw original body to `set.VerifyHTTPAction`. Use `VerifyHTTPActionStream` for binary/multipart with the actual fixed route limit, context-aware original wire reader and complete EOF. No re-marshalling, truncation or JSON-limit workaround. The API returns the original ActionAuthorization nonce/body digest/session binding/expiry.
3. After relevant await/provider/upload/confirmation, call `set.Revalidate` on that same original full session. A service/unconfigured/lock error is unavailable, not user revocation. Recheck the real current actor/account-generation and object/member/role authorization. Read scopes never imply write scope or merchant membership.
4. In the product's original transaction, verify ctx/deadline/proof expiry/current actor and owned object, then consume `(SessionBinding, Nonce)` together with the intended effect or durable unknown-intent marker. Lost responses must recover the original operation; new proof nonce does not permit a duplicated operation. This composition does not provide another nonce/relationship/account store.

AI concrete owned integration: current immutable238 `internal/aiproduct/canonical_session.go` constructs only `aiWalletPolicy()` Web and unconditionally verifies browser identity. Replace the owned authorizer with an explicit approved Web/Native set and preserve full verified Session alongside its existing ProductSession. Only Web performs browser identity verification; Native uses original verified account/device/current authority. Existing `authed` handlers must verify raw action and commit their own current actor/nonce/object together; the shared set alone must never change a deliberate business503 to success. Actual model/OS signer/Wallet approval/production key registration remain separate.

Mail/body wire maximum remains15,816,024 bytes; Media actual multipart route can use its existing <=512MiB fixed limit. Product scope/role maps and actual gateway public key registration are separate inputs, not inferred by this API. No legacy token fallback or new grant/renewal is performed.
