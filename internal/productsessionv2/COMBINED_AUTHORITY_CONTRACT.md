# Original private session and browser identity authority snapshot

Opt-in backend API: `Revalidator.RevalidateBrowser(ctx, originalSession, browserSSO, originalSealedBinding, fixedRouteScopes)` and matching `RegisteredClientSet.RevalidateBrowser`. Use the original `BrowserSSO.Binding` captured with the authenticated actor before work/awaits. Never expose that sealed credential, its grantToken or its local CSRF value in client JSON. A raw client grant/identity, fresh login, renewed grant or another browser association cannot substitute. The original private session still comes from mature `Authorize`/`VerifyHTTPAction`; the initial device proof is not consumed again.

The signed confidential POST `/v2/browser-sessions/product-browser-revalidate` contains exactly `clientId`, full original `session`, fixed `requiredScopes`, and `browser:{clientId,origin,grant:{grantToken,identity:{subject,account,generation,expiresAt},audience,scopes,expiresAt,csrf}}`. Existing BackendAuth binds full canonical body digest, exact path/method/client/key/issuer/audience/time/nonce. Browser Origin/Cookie/Sec-Fetch headers are forbidden; no CORS or browser credential response. It remains off under default adoption flags. Production operator backend registration is separately required; this source does not install keys or enable flags.

The actual Central BrowserStore owns one synchronous exclusive transaction. It checks the original grant token/client/expiry/revocation, original current approved identity and generation, original linked family/idle/absolute window when present, exact same-product registered identity client/origin/audience/identity scopes, account equal to the private session, and the original full private session/current device/control state/required private scopes via its existing synchronous authority reader. The V3 reader reads protected latest state before and after the kernel decision and fails closed on unreadable/changed state; V2 retains its original double protected file identity fence. No network, Promise, recursive same-store call, introspection-proof replay, refresh, family rebind, lastSeen update or renewal occurs inside the decision. Existing daemon composition already passes this exact synchronous reader; no store/daemon/BackendAuth change is needed.

Response is exactly `active:true`, identical full `session`, identical full `browser`. Go checks complete canonical equality, strict JSON/status/content type/no-store/bounds, and original private/browser deadlines again after HTTP. Revoke/generation/grant failures reject; outage/unconfigured/protected-state failures stay unavailable. CSRF is the original product-local sealed value covered by backend signature and response equality. Central does not mint or know the expected local CSRF secret; the owned HTTP business entrance must separately enforce its original Origin/CSRF check. Identity-only grants never supply a private permission, role or membership. AI keeps `ynx-ai-v1-sso-v1` / assistant origin / `ynx:ai:identity` / `identity:read`; Mail keeps `ynx-mail-v1-sso-v1` / mail origin / `ynx:mail:identity` / `identity:read`; private AI/Mail roles/scopes are independently registered and bounded. Default6/explicit13 and all registry data remain unchanged.

Owner ordering: capture fixed route scope policy, original PS and sealed browser binding; perform original action/body proof verification; after asynchronous work call this single combined read instead of two sequential private/BrowserSSO reads; then enter the existing owned transaction and recheck current actor/account/device/generation, object/member/role, original session/window, cancellation, nonce and effect. Never call a network revalidator while holding an owned store lock. Return to the same actor and existing account mapping; no renewal or policy inference. The authority snapshot is one decision, not a distributed lock across a later product write: a revocation occurring after the response is not prevented by this API. Product transaction/final cancellation fences remain required. Do not turn a business 503 HOLD into success before this exact source and operator-approved configuration are adopted.

Controlled source evidence: actual Central HTTP + original software approval fixture/protected V3 state for AI and Mail; both directions of revoke between formerly separate awaits; legacy and linked family success with unchanged deadlines/state; current generation, expiry, unavailable authority, account/device/scope/sealed-cookie mismatch, response tampering and expiry during HTTP. Direct Node tests exercise BackendAuth/header/default-off and the second V3 protected read failure. These are source/candidate QA only. No deployed protected registration, production approval, product integration, UI/Native actual approval or public readiness is asserted.
