# Normal original Auth/Cloud/Pay host

Build tags: `pay_pq pay_cloud pay_auth_source`. This package imports the complete actual Auth production supplier installed under `internal/authnativesource` and calls its real `NewOriginalPrivateNativePayServer`. The normal `ynx-pay-productd` entry consumes it under the same tag, retaining a nonnull Source partial before handling refusal. No supplier tests, PUBLIC controls, test seams or candidate commissioning records are installed in production.

`nativehost.New(parent, Resources, originalCoreHTTP, build, logger)` accepts Auth's exact existing resource type (a Go alias, not another wire or grant). It borrows the same original service Store through `Service.BorrowOriginalNativePayStore`, rejects another Store pointer even if its DATA matches, and leaves lifecycle ownership of Core Devnet/Application/BlockStore/Cloud reader/HTTP with their original hosting process. Request-scoped services cannot expose an unscoped Store. Missing typed parents are not recreated from HTTP or duplicated databases.

The five original handles are in-process dependencies. A separate product daemon cannot borrow Go objects across process boundaries, create a new Core ledger, or claim a TCP request is LINK's private original caller. The owning Core/Cloud process supplies these actual handles and mounts the successful returned Handler only through its original qualified LINK listener/route configuration. The standalone daemon has no such parents: it exercises the actual factory, retains its partial, logs unavailable and keeps its existing closed Native routes. Formal Root/issuer/current and sole SDK Pay-family grammar are independent gates; the empty admitted release inventory currently refuses before production I/O.

The missing shared hosting is normal CODE, not a request for an end user to supply Go pointers. P06 owns the product composition; Core retains the real ledger/Application/BlockStore and its normal constructor interface, and P04 owns its normal Cloud host/unique journal/opaque reader. Independent genuine commissioning and trusted proof anchors remain separate gates. Do not mount a second ledger, duplicate Cloud journal, fake handler or DTO/callback in place of those originals. A truly separate-process design requires the original owners' real controlled typed LINK boundary, not a reconstructed local object.

The original Pay parent constructor is now `payproduct.OpenNormalProduct(Config, NormalCentralPayEndpoint{Origin, APIKey, LINKConfigPath})`. The standalone `ynx-pay-productd` uses exactly this function too. Set `Config.PayAPI` to nil: the constructor always calls the original `NewProductionHTTPPayAPI` and `New(Config)`, captures that actual LINK transport, and returns one service/Store. It rejects replacement PayAPI clients before opening LINK or the Store. Core must supply an explicit owned QA StorePath and the original normal endpoint/key/LINK configuration; no existing user data is copied or concurrently opened under another parent. All other existing Config validation and optional product providers retain their original behavior.

Retain the returned `*NormalProduct` even on error and call its `Close` on constructor rollback. `Service()` returns the actual original parent only while ready; `BorrowOriginalNativePayStore()` gives that same Store to Auth. Store is memory plus its original atomic durable file and has no held descriptor or independent Close. There is no second database to initialize/close. After stopping admission, stop/join the original retry worker and drain original requests, close the owned Native Source successfully, then close `NormalProduct` to release its captured central LINK transport. A failed drain or Source close must retain this parent and cleanup debt. `Close` retains its own first close error rather than accepting a later transport no-op as success. The standalone daemon now implements this ordering, including worker cancellation/join. The shared Core host owns its outer all-parent sequencing.

`--native-source-self-check` calls that exact factory without credentials, network, ledger creation, bill lookup, signature or funds. It reports linked/ready/partial/first cause and cleanup, returning2 when Source is unavailable. It is a diagnostic only and cannot select a runtime or activate authority. A build without the supplier tag reports source-not-linked rather than substituting another Source.

Shutdown ordering is stop new admission, retire Source, drain original server requests, then close the owned Source. The original borrowed parents are never closed by this module. Runtime retains the Source/first cause and cleanup debt; retire cannot continue to report ready. The normal daemon handles SIGINT/SIGTERM, stops its original retry timer, drains before Source.Close and preserves nonzero startup/listen/drain/cleanup failures. UNKNOWN remains original query-only; no Source operation signs or resends anything here.

If the daemon's actual HTTP drain times out, it returns nonzero and preserves that drain error without calling Source.Close while original requests are still using it. Its held Source cleanup is still pending; this is not a successful drain or cleanup receipt. A real blocked HTTP request regression covers the timeout and subsequent successful drain. It does not qualify an admitted business Source or the original parent owner's shutdown ordering.

Prepared P06 composition consumes the complete LINK640 package, P04 frozen79 Cloud Go leaves, Auth frozen8 production Go leaves, original fixed Core overlay and current Pay. Each supplier is hash checked and originals remain untouched. The older d6/Cloud composition and Mac2b installed client are preserved; this Go-only module does not hot-update that app or migrate its identity. The combined actual Unix caller/PayStore race and the normal empty-Root/same-Store tests are new deltas; old money/signature suites are reused.

The formal SDK-consumption successor replaces exactly three of those eight Auth production leaves (assembly/factory/runtime_sdk), with all eight consumed as one frozen delivery. Its actual sole family is `pay-native-cloud-bill-source-v1`, selection `payNativeCloudBillV1`, and explicit linux/macos/windows release policy; no GOOS default exists. P06 consumes its real normal factory/API unchanged. Supplier tests/PUBLIC fixtures are not installed into production, and the supplier's completed normal package/Go delta evidence is reused. Genuine commissioning inventory remains empty. P04's new normal Cloud host is a separate original-owner delivery; never pretend the old r1 reader-only composition already includes that host.

`OpenProducts(ctx, ProductsConfig, build, logger)` now performs the actual product parent composition: one `cloud.OpenOriginalPrivateHost`, one `payproduct.OpenNormalProduct`, and their same opaque bill reader and Pay Store. P06 consumes the entire frozen P04 private-host delivery's 39 production Go files and the formal Auth eight-leaf delivery, without their test material. The formal Auth successor still declares a universal Core tuple which Core has now confirmed does not exist in normal operation. That tuple is deliberately absent from the new products API. Until Auth supplies the engine-specific normal Source successor, `NativeSourceStatus()` reports `PAY_HOST_ORIGINAL_ENGINE_SOURCE_CONTRACT_NOT_LINKED`, and Pay uses its actual original `NewClosedProductionServerWithLogger` handler to refuse protected routes. The real independently available Cloud handler remains usable through `CloudHandler()`; no successful Source or fake receipt is substituted.

Keep every nonnull `Products` partial even after constructor error. `Retire` stops admission and cancels its Pay retry worker plus Cloud workers. `Join(ctx)` must finish product requests, the retry worker and the actual Cloud host's workers/requests. A cancelled Join does not qualify a Close: `Close` preserves `PAY_HOST_CHILDREN_STILL_DRAINING` and the actual parents. After a successful complete Join, close the real Auth child first, then the owned Cloud host, then the original Pay LINK transport. An actual child close failure retains the later parents. The first close cause remains visible even if a later successful drain permits cleanup. Borrowed Core resources are never closed here. Private LINK listener ownership, its own Retire/Join and Serve goroutine completion are additional enclosing-host duties; retain and explicitly close the original listener even if Serve fails before transfer. Do not unlink an existing endpoint or replay an uncertain operation during recovery.

Core has confirmed the normal engines are distinct: native is the actual Devnet plus API handler; BFT is the unique Application plus Node-owned BlockStore, with the original `ProofSourceView`/live proof control. Application does not contain Devnet. Auth owns the necessary engine-specific typed contract correction, preserving merchant fencing, actual authority and independently authenticated proof anchors. P06 must not construct a second ledger to satisfy the old struct. Thus these product parent/lifecycle checks do not claim a full Core-hosted Source, matching Main installation or merchant invoice/payment/refund acceptance.

`OpenPrivate(products, PrivateConfig)` mounts only these genuine handlers through the existing LINK `ListenPrivate` and `NewLocalCallerServer`. `/v5/pay/` routes go to Pay; other explicitly registered routes go to Cloud. No TCP listener or request-selected handler exists. The original request pointer is preserved. `Shutdown(ctx)` retains and explicitly closes the original listener, retires LINK/product admission, waits for LINK registered handler drain and the original Serve goroutine, then drains/closes Products. Timeout or child failure retains the remaining parents and first cause. LINK does not unlink an existing endpoint; use an explicit reconciled endpoint or fresh QA generation and never replay UNKNOWN. `cmd/ynx-pay-private-host` is the normal private-only entry using these same constructors and original SIGTERM lifecycle, with exact operator configuration and no Source/Root activation flag.
