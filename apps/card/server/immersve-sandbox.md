# Immersve Test adapter boundary

This Card-owned server module is dormant by default and is **not** wired to the public Card API. It pins `https://test.immersve.com`, uses server-only API-key headers and an explicit per-owner cardholder account binding, and offers read-only funding-source, non-sensitive card, and partner webhook-delivery queries. The read-only doctor never outputs credentials. No caller can supply another host or a partner account as a cardholder shortcut.

Incoming Test webhooks require the official RSA-SHA256 signature over the exact raw body, matching fixed Test issuer, listener, partner and bound cardholder account. Only message/topic/digest/timestamps enter the encrypted Card SQLite state under a separate owner-scoped provider-metadata key. Stable message IDs deduplicate. No webhook payload is written into the YNXT ledger, and a simulator deposit is not a chain transaction.

`createFundingSource` and `createCard` explicitly fail closed. The official public [Execute Simulator Deposit model](https://github.com/immersve/immersve-docs/blob/1136396fb7489e33868f3022402ba6ecd1ef2cd4/imsv-docs-docusaurus/openapi/endpoints/simulator/models/execute-deposit-request.yaml) specifies `amount` (a decimal string in the funding source token's minor units) and `fundingSourceId`. The adapter plans exactly this body and has a controlled `POST /api/simulator/execute-deposit` path. It requires a short-lived operator ticket, exact QA cardholder binding, YNX-owned Test credentials, explicit write enablement, a per-call amount cap (hard ceiling 100000000 minor units) and a persisted call cap (hard ceiling 10). All are disabled by default. This source slice did **not** send a provider POST.

Before sending, an owner-scoped `UNKNOWN` operation is durably committed with one attempt reserved. A concurrent or restarted caller with the same operation ID receives that record and never sends again; a changed body conflicts. A valid 200 response records only the provider interaction ID, not a Card credit. A network/timeout/invalid/non-200 outcome stays `UNKNOWN` and is never automatically retried. Read-only, cursor-paginated Funding Source Interactions may assist a human with reconciliation, but matching amount/time cannot prove which UNKNOWN write succeeded. The [official interaction model](https://github.com/immersve/immersve-docs/blob/1136396fb7489e33868f3022402ba6ecd1ef2cd4/imsv-docs-docusaurus/openapi/endpoints/funding-sources/models/funding-source-interaction.yaml) has no client idempotency reference. The provider's idempotency and ambiguous-outcome guarantees remain undocumented for this endpoint, so an approved operation lease and manual resolution policy are still required before any real Test write.

The supported Test-only source is **not** a claim of an issued card, approved application, available YNXT balance, real payment, YNXT or tUSD provider support.

Official contracts: [authentication](https://docs.immersve.com/guides/authentication/), [funding sources](https://docs.immersve.com/api-reference/list-funding-sources/), [non-sensitive card details](https://docs.immersve.com/api-reference/get-card/), [simulator](https://docs.immersve.com/guides/simulator-funding-protocol/), [webhooks](https://docs.immersve.com/guides/webhooks/), [delivery recovery](https://docs.immersve.com/api-reference/list-webhook-notifications/), [Postman examples](https://docs.immersve.com/resources/postman-collection/).

Activation requires a trusted server composition, persistent CardStore, YNX-owned Test credentials, owner-to-cardholder binding established independently of untrusted requests, listener registration and explicit release authority. Until then, the public Card remains Testnet simulation and the existing Card YNXT receipt path remains the sole source of spendable test balance.
