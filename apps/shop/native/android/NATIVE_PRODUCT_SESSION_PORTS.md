# Android protected ports for the adopted Native SDK

The sole A shared source adopted the Native consumer in commit `34f58c74a79a35cb7b95fbe46e1cd4b8a51de40e`, tree `f98bd7a00c1f9bf725735b4629a5666b3fe3676e`. The independently reviewed standalone artifact is SHA256 `a7d0f2a8bac2780f3b4db39a904245947cf5ed7a20ea62933b18e7e5369c8f82`. This product implements its runtime ports; it does not fork the protocol or shared SDK.

`NativeProtectedRuntime` is a package-private owner port. It requires the actual registered package `com.ynxweb4.shop`; `.debug` is not an approved Native tuple. It creates a separate nonexportable AndroidKeyStore `secp256r1` key, reports protection using the actual key metadata, signs the original canonical protocol bytes with SHA256withECDSA and returns DER/base64url. CSPRNG returns exactly32bytes. Existing legacy keys and records remain unchanged. This code is compiled, but actual device protection is not yet verified.

`NativeProductState` stores context and all namespace mutations in one encrypted SecureStore snapshot with confirmed write/readback. Account selection increments the persisted generation. Every sign/storage/open uses the original context inside a synchronized authority check; no Javascript-only fence substitutes for it. A failed write/readback disables this live runtime until protected cold recovery. Old generations and malformed records are preserved and cannot be silently adopted. The supplied SDK namespace receives a separate original context binding, and the fixed five Buyer keys exclude cross-product access.

The seven storage ports include a durable synchronous negative-authority marker, exact original revocation-intent persistence/upgrade and atomic exact-target cleanup. A newer unrelated session and its pending records survive old-target cleanup. Signing and opening are blocked while the original current-context revoke is pending. The revoke scope uses the actual existing SDK native chain identifier `ynx_6423-1`; EVM6423is not its substitute. Actual standalone SDK comparison verifies this digest and canonical string bytes.

OS opening snapshots the original input/context before posting to the main thread. It checks the exact registered `ynxwallet://authorize?request=...` URI, prepared request bytes, device/application/callback/native chain and the exact three Buyer scopes. Opened remains a launch receipt. A Seller grant or extra URL parameters are refused. A missing Wallet handler returns false.

## Remaining consumer integration

These ports are not yet attached to MainActivity, WalletAuth or ApiClient. The existing compatibility client is not a canonical Native consumer. Next, instantiate the adopted standalone SDK in an owner-controlled native bridge, supply its included branded Gateway adapter with A's actual protected HTTPS authority configuration, route original OS callbacks to `handleReturn`, and generate SDK proofs for the actual bounded API wire body. Preserve the distinct Buyer/Seller scope decisions and retired original records. The bridge must expose no ports to remote pages or arbitrary browser/Intent input. Each private request must finish body readback, use the exact SDK proof headers and current backend actor/nonce/commit checks, and cancel late results on context changes. Do not enable these ports via a software-key/debug-package fallback, or treat source tests as installation or user-flow acceptance.
