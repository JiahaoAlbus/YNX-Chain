# Native workbench consumer continuation

This successor inherits aced4f0cf and the existing Wallet/guest project store. It does not replace the mature OpenVSCode editor with guest Monaco features.

The actual React consumer now observes preparing/stopping sessions with at most eight automatic catalog GETs at 2.5-second intervals. A still-pending runtime then requires explicit Refresh, not an infinite background identity renewal. These reads do not invoke identity activity or dispatch launch/Stop. Session state is visible, failures preserve files and writer protection, and manual recovery remains explicit. Project/account changes and unmount cancel the timer through the existing epoch lifecycle.

Only a running, non-failed UUID session of the selected project with the exact relative /sso/core-open?sessionId=<id> entry can expose editor/Tools links. Arbitrary executor origins, token-bearing query strings, mismatched locators and non-running sessions are withheld. Stop also checks the selected project and current catalog before dispatch. Unconfigured runtime and unverifiable editor entry have direct product messages.

Mac WKWebView previously had no new-window delegate, so trusted local target=_blank links could silently disappear. The actual delegate now loads clicked local Tools pages into the current view. Public HTTP(S) links use the system browser; remote documents do not receive the local native file/Keychain bridge. Script popups, untrusted source frames, blank/file/javascript destinations cannot create a privileged local view. Ten decisions are tested by compiling and invoking the actual native source without launching UI. This is not actual locked-screen GUI acceptance or a full OpenVSCode native process.

Eight actual React/Chromium controlled-route checks cover preparing-to-ready, revoked identity, canonical/unsafe/recovery/stopping locators, bounded observation and manual refresh. The inherited panel suite and nine actual local HTTP identity-binding cases also pass. All controlled routes are isolated test authorities, not real Wallet or a production executor. Current source compiles and builds. Mac lock does not prevent this owned source work.

## Exact A mount surface and required operator inputs

The existing services/gateway/src/server.mjs owns consumer mounts: loadCoreAdmissionAdapter receives stateDir/workspaceStore/runtimeProfileService; Developer SSO supplies canonical verifyIdentity and owner drain; CodeOSS supplies persistent broker/writer admission; the per-session HTTP/WS proxy is mounted only when an admitted driver exists. This consumer wiring is implemented, not a request for A to rebuild the product UI.

A installs the protected root-owned /etc/ynx-developer/adapters/<name>.mjs and selects YNX_CODE_CORE_ADAPTER_MODULE. createDeveloperCoreAdmission(context) must supply exact launchURL, sessionForHost, originForSession, driver.start/stop/connect and the reviewed persistent/quota-isolated project mapping. The runtime must preserve pinned OpenVSCode 1.109.5, reviewed activity bootstrap and current 22px original-brand derived manifest. Existing shared backend key file/id remain YNX_DEVELOPER_CENTRAL_BACKEND_KEY_FILE and YNX_DEVELOPER_CENTRAL_BACKEND_KEY_ID; their values must not be provided by an extension or project. Public callback is https://developer.ynxweb4.com/sso/callback and admission remains a short one-use exchange, never a kernel token embedded in a URL.

No approved configured full-kernel executor was established by this continuation. Existing LXD driver code is within the previously stopped execution scope; it has not been run or replaced. Neither reference Chrome workspace 41943 nor local Mac sandbox qualifies as the formal shared executor.
