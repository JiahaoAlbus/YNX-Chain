# Existing installed-client entry handshake

The normal Web home remains the canonical Wallet-project entry. Older installed Windows clients already poll window.__ynxDesktopHost({command:'state'}) at the exact trusted parent origin/root. The frontend now exposes a temporary entry dispatcher there: only the exact state query selects the retained Workbench; it returns schema ynx-desktop-host/v1/status not-ready while React mounts it. The existing Workbench dispatcher then reports the actual restored project, workspaceReady and editorReady. Save/new-file/import/export commands and unknown fields are refused before mounting. It does not enqueue/replay any file command. Effect cleanup never replaces a newer dispatcher.

The existing same-origin/top-frame/path guard also protects this entry. Same-origin child frames and other origins cannot activate it. No WebView2 fingerprint, privileged message channel or host object is added. The provisional Windows document-start marker has been removed from both the client source and frontend route selection; older installed clients do not need a new marker to use their existing state handshake. Mac's independently restored document-start workspace bridge and the explicit guest recovery route are retained.

Production-build browser evidence:7 desktop-entry checks and6 homepage checks passed in real React/Chromium. Exact built bytes are served through controlled local routes at the document origin; no HTTP/WS traffic forwards to production. Desktop checks execute the actual old state contract, load real Monaco, restore the existing project, create a reviewed file, acknowledge a local recovery save and reopen the same profile. They also cover refused pre-entry file commands, invalid fields, child frame and wrong origin, and preservation of damaged profile bytes. Homepage checks cover phone/desktop dimensions, private project selection/creation/open ticket, account change and Mac/guest recovery.

The terminal transport is deliberately closed in this fixture. Its outcome is unconfirmed, so actual existing guards report localSaved:true/remoteSaved:false and block server overwrite; the test preserves that behavior, never fabricates a terminal exit or remote save. The original incorrect remote-save expectation is preserved as diagnostic evidence. This is browser/contract compatibility, not installed WebView2/native clipboard/OS persistence acceptance, actual OpenVSCode editing/terminal or real Wallet/AI/capacity evidence.
