# New canonical-user project flow

Signed-in users can now create an empty project directly from the full-workbench entry panel, without manufacturing or copying a guest project. The name and account are displayed together and require explicit review. Creation selects the returned project in the existing Wallet project catalog; opening it uses the existing native admission, revision and persistence pipeline.

POST /runtime/identity/projects is a product-owned local workspace operation. It verifies the canonical backend grant before and after reading the bounded request, checks same parent host/origin and the displayed identity binding, and accepts only approval, approvalId and name. It does not add a shared permission, signing scope, terminal capability or deploy grant. The v4 UUID yields wallet-<approvalId>; no caller can select an existing destination. The existing workspace store commits empty files/folders/open/active with expected revision zero and an idempotency key bound to the reviewed UUID/name. Retrying the same request returns its stored result; changed names using that approval fail. Native adoption/writer guards remain intact.

The UI retains the reviewed name/UUID after an uncertain response for explicit manual retry; it never automatically repeats creation. Name changes clear review and intent. Account changes/sign-out/401 retire approval and intent; a late UI completion cannot switch the current selection. Existing guest files, owned files and drafts are retained.
