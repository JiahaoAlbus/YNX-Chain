# IDE original service pipe development R1

Development source only. Do not select this successor for a release or enable
its success path before the original SDK acquisition, Native consumer and their
exact formal source pins match. This document is not admission or Source supply.

The SDK owner's matching development contract is
`packages/wallet-auth/integration/IDE_PRIVATE_SERVICE_PIPE_DEV_R1.md` in its R3d
stage. SDK owns its sole decoder, original journal, execution and terminal proof.
IDE owns only its existing stdin pipe, private result files and window retirement.

## Normal entry and trust boundary

`code-server.mjs` calls `attachOriginalServicePipe` with transport coordinates.
It rejects provider/original objects and currently retains the original eight
field `ORIGINAL_PRIVATE_SERVICE_NOT_SUPPLIED` response. No SDK protected graph
loads on this missing-supplier path. Normal startup has no injectable provider.

`attachAcquiredOriginalServicePipe` is module-private success CODE. Only the
future fixed SDK acquisition may connect it to its actual acquired owner. It is
not exported in production; the external PUBLIC test loader exposes its unchanged
body only for component controls. Neither those instruments nor Node delivery
`descriptor/assertCurrent/close`, an R31 daemon owner, or a DTO is qualification.

## Existing transport, two phases

Native sends the existing dispatch/cancel frames with original
`id/document/instance/projectId/workspace`. Dispatch adds `canonicalInput`, kept
as an exact opaque string. Only the SDK decoder selects its original
`operation/phase/requestId`. No second parser is introduced.

The private result wrapper schema is `ynx-ide-original-service-pipe/v1`:

* Provisional: full local binding, `status:response-pending-terminal`,
  `entered:true`, `unknown:true`, exact `resultRaw`, SHA256 `resultDigest`.
* Parent receipt: stdin `action:original-service-received`, full local binding,
  `resultDigest`. There is no renderer ACK method. Native checks the actual
  document token and generation again before sending it once.
* Terminal: full local binding, `status:terminal`, `entered:true`,
  `unknown:false`, the same digest; a separate `wallet-<id>-terminal.json`.

The response is the SDK's canonical outer `{status,headers,body}`. Preserve its
inner body string and headers. A parent receipt proves transport receipt only,
not Native business terminal proof or human receipt. The renderer Promise stays
pending until Native matches the SDK-confirmed terminal and retained raw bytes.

The backend ACK uses only its original decoded row and retained result. It then
calls SDK `selectCurrentOutcome`, requiring the same result reference and bytes,
`terminal:true/unknown:false`. An original already completed by the owning SDK
backend is not ACKed again. A forensic `selectOutcome` flag is not sufficient.
No current observation can reconcile a cancelled, poisoned or cold request.
Daemon service terminal, the actual acquired client terminal, and the Native
parent transport receipt are distinct. A server DTO or server-side ACK cannot
make the client row terminal or skip that client's own required ACK.

## Bounds, publication and lifecycle

SDK request limits remain legacy 65536/49152, v3 262144/196608 and v4
65536/49152 envelope/body bytes. Only the service's escaped local transport
wrapper permits 576 KiB. Other subscriptions retain their own 256 KiB bound;
ordinary P256 signing is unchanged. The current Native service response limit
is 65536 outer bytes, not HTTP's 1 MiB limit. The service-only result reader
permits a 192 KiB escaped wrapper; the ordinary shared JSON reader stays 16 KiB.
These transport bounds do not prove that every 64 KiB response fits the separate
8192-byte Native immutable terminal journal.

Private publication creates a 0600 staging file exclusively, writes/fsyncs/closes,
rechecks directory identity and original current, then links without overwrite.
Post-link current must pass before the staging link is removed. A failed fence
leaves nlink=2 evidence; Native requires nlink=1 and cannot consume it as success.

Claim the stdin action routes before awaiting SDK CODE. Requests wait for CODE
without being lost to a running Go reader; cancellation/close fences them before
SDK entry. Duplicate receipt cannot invoke ACK twice. Wrong binding/digest,
late result, failed ACK/current/IO, or uncertain close cannot release success or
replay the operation. Retain the original raw/result, first cause and UNKNOWN.
Falsy failures retain explicit presence through parent cleanup and shutdown.

This channel drains its transport tasks. The acquiring backend independently
retains and closes its original SDK/Native resource; transport cleanup is not
permission to release that resource or discard unresolved originals.

## Still required

publish its matching fixed acquisition and durable original journal contract;
R31 listener CODE alone is not this child consumer. Restart needs real original
request recovery, Host adoption, Native proof and current; memory rows are not
a cold journal. No restart dispatch/replay endpoint is implemented here.

The retained frontend Product Session factory has not been silently replaced.
Its existing optional native bridge is not yet a complete new SDK/reference
business caller. Consume the sole owner's compatible client export when formally
supplied, preserving the same runtime and purpose limits. Actual Native/App,
Wallet login/deployment and website acceptance remain separate gates.
