Read-only Pay event consumption previously used `json.Unmarshal` into `map[string]any`, rounding JSON integers via float64, then unchecked float-to-int/string-to-int conversion. This could turn original 9007199254740993 into 9007199254740992 or invalid/missing input into fabricated zero. Finance now decodes each original raw event with UseNumber and validates the first present amount field as exact signed int64. The preferred present field cannot fail and silently fall back to another alias. Fractional/exponent/overflow/null/bool/invalid-string/missing amounts are not receipt values. Valid remaining receipts are preserved; an owned invalid amount marks Pay source unavailable/partial-invalid-records with a fixed non-sensitive diagnostic.

This is Finance consumer code only. No Pay implementation, settlement, authorization, event publisher or schema/state migration changed. Existing signed integer/string inputs and exact zero remain compatible; negative int64 values preserve source semantics without treating them as authorized payments. The existing browser formatter only renders non-negative safe integers and displays localized unknown for unsupported values; this patch does not claim arbitrary-large browser formatting or new public business evidence.
