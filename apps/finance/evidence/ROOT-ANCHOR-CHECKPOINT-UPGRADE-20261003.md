# Independently verified root-anchor checkpoint upgrade

This source successor enables the mature `recoverEndpointAuthorityRootAnchor` algorithm to commit a higher root at the existing sequence and payload. It does not activate authority, issue a manifest, extend a key window, or alter a user's grant.

The SDK creates an opaque one-use WeakMap capability only after an independently supplied canonical root SHA256 matches, the historical anchor signature verifies at issuance, a strictly later current manifest independently verifies at the real clock, and the clock remains monotonic. The capability binds the exact storage object, previous checkpoint and target checkpoint; failed or completed recovery removes it. Finance Node and browser CAS require this capability for same-sequence root changes. Node additionally requires the target equal its configured anchor. Same/lower roots and same-sequence payload changes cannot use this path. Existing same-checkpoint idempotence remains for normal readers; recovery itself rejects same-root requests.

Committed journals preserve the existing transition schema, exact previous linkage, bounds, trusted-clock high-water and filesystem protection. Reading an existing higher-root/same-sequence/same-payload transition is allowed, including after process restart. The standalone `checkpoint-readonly.py` has the same semantic predicate but cannot initialize a genesis or repair a committed marker: UID995, existing full prefix, directory/leaf descriptors, NOFOLLOW, owner/mode/nlink/size, strict JSON, safe integers and the 10,000-row bound remain mandatory. Local tests replace only the fixed UID995 assertion to run under the current unprivileged test UID; this is not Host995 admission.

The browser test now explicitly aliases the current SDK source, rather than resolving the previous worktree through an existing node_modules link. The original missing-export failure is retained in `/tmp/ynx-root3-anchor-browser-first-20261003.log`. The first Node test used the wrong expected error for invalid root zero; that failure is retained in `/tmp/ynx-root3-anchor-node-first-20261003.log`.

Deployment is NOT performed by this source. Root2/54 durable state, expired unsigned55 and its STARTING issuer intent are preserved. A new independently pinned Root3, retained old key windows, a protected independent issuer key, complete strict receipts validated before signing, Go/Node/Web prefix shadows, and a reviewed maintenance/release closure are required before real activation. No caller-supplied root automatically gains CAS authority. This does not close Finance intermittent503 or any installed/public business acceptance gate.
