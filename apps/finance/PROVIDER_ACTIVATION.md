# Controlled activation — NOT a live trading runbook

1. Keep `FINANCE_TRADING_ENABLED=false`, `FINANCE_SANDBOX_WRITES_ENABLED=false`, `FINANCE_LIVE_ENABLED=false`. Existing Finance keeps working. No RPC changes are needed for Broker integration.
2. Supply only a server Secret Manager reference or protected service configuration location, never credentials in chat, Git, browser variables, logs or command arguments. Copy the variable names from `.env.example`; do not dump a populated env. Select the actually provisioned Broker authentication method; personal Paper keys are not substitutes.
3. Set testnet/6423 + sandbox and the exact schema origins. `private_key_jwt` currently fails unsupported. Restart the Finance service through its normal authorized owner deployment; there is no hot reload or implicit activation.
4. From `apps/finance`, run `npm run finance:doctor`. This checks config only, makes no network call, prints only safe fixed diagnostics. Disabled is not healthy/authenticated Sandbox. Enable the module flag only in an approved isolated environment to inspect its UI; missing keys leave orders disabled.
5. Only with permission to test the provided credentials, run `npm run finance:doctor -- --network-read-only`. It makes at most one token acquisition and one assets GET, no automatic retries, no accounts/identity listing, no create/fund/order. It verifies only this capability, not ownership, data license or full Sandbox workflow. Do not run concurrent Sandbox load tests.
6. `npm run finance:sandbox:verify -- --network-read-only` performs the same bounded real assets check as doctor, records only read capability and cannot enable public trading. Without that explicit option, `npm run finance:sandbox:verify` fails closed with `BLOCKED_OFFICIAL_SANDBOX_WRITE_CONFIRMATION`, makes no external calls and never sends a test order. Durable mapping, exact Wallet proof, one-time consumption and outbox now exist locally, but provider POST and its public route remain intentionally unwired. A future write test still requires official credentials, account allowlist, virtual-funds-only constraints, an immediate test-account confirmation and a separately reviewed adapter wiring checkpoint.
7. Keep simulated USD/equity separate from YNXT; never claim an off-chain order has a chain transaction hash. Complete refresh/restart/unknown/reconciliation and cancellation-race tests before public activation.

Rollback: set the module flag false and restart only with deployment authority. State v2 is a lazy, non-destructive migration from v1; take an authenticated backup before deploying it. An older binary must not overwrite a state file after v2 has been written. Public release and secret installation are not performed by the development/test commands.
