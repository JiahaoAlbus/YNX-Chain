# Finance Phase3 stdin deployment lease successor

Central's latest Phase3 review accepted the separate manual-rollback semantics but found the production transport undefined: the local fixture wrote the new rollback lease directly to a local path, while production needs a reviewed command object to place a future separately signed lease under `/opt/ynx/leases/finance`.

This successor separates the two modes. Deploy still requires all lease-owned stage, backup, release and release-container paths to be absent. It creates the release container no-replace, verifies the signed path/UID/GID/mode, moves the candidate, and emits parent tuples, the container's stable identity/empty/present tuples, the backup tuple, the candidate release tuple/inventory, and candidate service PID/NRestarts.

A later external or browser verification failure requires a wholly new Central-signed `FINANCE_ROLLBACK_FIRST_PRODUCTION_MANUAL_ROLLBACK` lease built from that immutable success receipt. Rollback requires the exact present container, release inventory, backup, candidate current link, candidate environment, unit/Caddy hashes and service PID/NRestarts. Every check uses an explicit fail-closed guard before the first write; it does not depend on implicit shell error behavior. Only after all checks pass does it restore the old runtime and remove the exact release plus exact empty container.

The new manual-rollback bootstrap receives exactly one signed rollback-lease body on stdin. It fresh-binds the existing Finance lease-parent tuple and retained executor tuple/SHA, requires both final and pending target paths absent, writes a no-clobber pending file in the same directory, checks identity/bytes/SHA/JSON/kind/id/mode, atomically renames it, then invokes the retained executor exactly once. Partial input cleans only the exact pending inode. Foreign final/pending files, parent replacement and post-rename target substitution fail closed and remain preserved. The lease body is never printed.

Before deploy begins, any partial placement is removed only when the exact created file identity still matches. Automatic failure rollback retains the same exact cleanup rules. The actual-shell suite now performs a real successful deploy, simulates the later external-verification boundary, transports a separate signed-style rollback lease over stdin, invokes the real executor once, and proves exact old-runtime restoration and release/container cleanup. Foreign inventory and substituted-release variants fail before mutation and remain preserved. Transport-specific malformed-body, foreign final/pending, parent replacement and target-substitution tests also pass.
