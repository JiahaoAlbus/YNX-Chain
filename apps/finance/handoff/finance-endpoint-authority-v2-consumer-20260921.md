The Finance consumer now uses the shared `sdk/js/endpoint-authority-v2.js` verifier. It does not copy its Ed25519, canonicalization, policy or progression logic. Server requests pass a fixed absolute Node executable and script with no shell and no request-derived arguments. If v2 is absent, partial, expired, revoked, equivocated, clock-rolled-back, CAS-conflicted or storage-lost, Product Session fails before Wallet Gateway network access; guest and Standard Wallet remain independent.

Web now obtains its verified public authority metadata from the shipped same-origin `GET /api/endpoint-authority/v2/config` path; no external bootstrapping global is required. The server verifies the signed root/manifest before returning them and includes its durable checkpoint and trusted-time anchor. The browser uses that server checkpoint as its recovery floor, so a complete IndexedDB plus localStorage clear cannot reset progression to the trust-root anchor. It still uses one IndexedDB read-write transaction for CAS, a marker for partial loss detection, a monotonic trusted clock, cross-tab invalidation and re-verification at begin, restore/callback, proof and order-persistence boundaries.

Malformed or missing v2 proof headers are rejected before the external Node verifier can start, and verifier subprocess concurrency is bounded. Node uses no-follow file-handle reads plus an append-only CAS: it fsyncs a complete transition, then atomically hard-links it to a fixed name derived from the previous checkpoint. It never reopens the checkpoint pathname for mutation, so a pre-existing symlink or competing transition is rejected without writing through to another target. Per-transition commit markers detect deletion, a published transition with a missing marker repairs safely, and a marker without its transition fails closed. SIGKILL before publish leaves current state unchanged; SIGKILL after publish is recovered from the complete hard-linked transition. Twenty rounds of eight simultaneous OS processes each produced exactly one successful CAS and seven stable false results.

The checkpoint prefix must be in a service-owned directory with exact mode 0700. Every ancestor to the filesystem root must be a real directory, owned by root or the service uid, and not group/other writable; the complete chain identity is checked around publication. A persisted genesis remains historical across an accepted trust-root rotation, while rotation back to an older root and any transition root/sequence/trusted-clock rollback fail closed. Mobile 1.2.0 exposes capability rejection only: Expo digest/SecureStore are not presented as Ed25519/durable CAS.
