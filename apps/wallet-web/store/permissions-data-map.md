# Permissions and data map

Review date: 2026-09-06. Paths below are relative to `apps/wallet-web`. This is an implementation inventory, not a statement that a publisher has accepted policy obligations or that a store has approved the extension.

## Browser permissions — dashboard justification text

| Permission | Actual use and justification | Source |
| --- | --- | --- |
| `storage` | Keep the password-encrypted vault, public account, approved site origins and durable original-transaction recovery/history locally. Session storage holds short-lived approval/replay records. No `storage.sync` is used. | `extension/service-worker.js`, `src/extension-vault.js`, `src/extension-provider-permissions.js`, `src/extension-broadcast-journal.js`, `src/extension-sensitive-policy.js` |
| `scripting` | Repair provider injection only on the active eligible HTTPS tab after a toolbar action. Inject packaged transport/provider files; no downloaded script execution. | `src/active-tab-policy.js`, `extension/service-worker.js` |
| `activeTab` | Identify and repair the DApp tab selected through the extension action. This grants neither an account connection nor a signature. | `extension/service-worker.js`, `src/active-tab-policy.js` |
| `https://*/*` host scope and content-script matches | Announce an EIP-6963/EIP-1193 YNX provider at document start on top-level HTTPS DApps, including sites not known in advance. The bridge accepts structured wallet requests; it does not scrape page text, forms, cookies or history. This broad access must be prominently explained; automatic discovery is the reason it is retained. | `src/extension-manifest.js`, `extension/content-script.js`, `extension/page-provider.js` |

`tabs.get/query`, navigation notifications and requesting origins maintain the live request/site boundary. There is no `history`, `cookies`, `webRequest`, `nativeMessaging`, `identity`, `downloads`, `clipboardRead`, `geolocation` or telemetry permission. The `incognito: not_allowed` candidate excludes private windows rather than claiming isolated private storage. Firefox container permissions use browser-owned sender.tab / tabs.get cookieStoreId; reading this metadata requires no cookies or contextualIdentities permission. Missing Firefox context fails closed. The encrypted vault and account-level recovery journal are shared, with explicit connection required in each container. Installed verification remains pending.

中文权限说明：`storage` 保存本地加密账户、连接权限与原交易恢复历史；`scripting` 与 `activeTab` 仅为用户当前选中的 HTTPS DApp 修复钱包注入；HTTPS 全站范围用于未知 DApp 在页面加载时发现独立 YNX 提供者，不代表扩展读取浏览历史或任意表单。连接、签名和转账仍分别受授权限制。

## Data handling and recipients

| Data | Local handling | Outside this browser | Control / retention |
| --- | --- | --- | --- |
| Wallet password and recovery/private key | Password derives a non-extractable AES-256-GCM key using PBKDF2-SHA256, 600,000 iterations. Private-key ciphertext is in `storage.local`; unencrypted key material/password exist during local creation/unlock/signing, and the recovery key is displayed for offline backup. Public metadata is not encrypted. | No extension code uploads the local password, private key, encrypted vault or recovery key. Internal extension messages are within the browser. | Remove account deletes its encrypted vault, public provider account and site permissions. No promise that JavaScript strings, OS/browser backups or compromised devices are securely erased. |
| Public wallet address, public key, creation time | Vault header and provider account persist locally. UI uses `ynx`; protocol uses equivalent `0x`. | Approved DApps receive the public address. RPC receives address/hash/query parameters for requested balances, fees, nonces and transaction status. | Address is a persistent pseudonymous account identifier. Revocation cannot erase information already returned. |
| Requesting site origin, browser/container and tab/document context, permission time | Firefox permission records bind origin/account/cookieStoreId; Chromium retains origin/account scope. Old unscoped Firefox grants are retained but confer no permission in any Firefox context. Tab context and short-lived requests support routing/cancellation; transaction history includes the source origin. | The extension does not send a browsing-history feed or separate current-tab URL field to the RPC. The requesting DApp already knows its own origin. | Revocation removes only the current browser-context/origin grant; stored transaction history remains. A grant in another Firefox container cannot be reused or revoked by the requesting container. Container metadata is not sent to the DApp or RPC. |
| Message / typed-data request and signature | Visible review, short-lived session record, local password unlock, then signing. | Approved signature goes to the requesting DApp, which may send it to its service and authenticate or authorize actions. The extension does not independently upload the raw message to the RPC for message signing. | Reject before signing; the extension cannot invalidate a signature already received by a DApp. Session cleanup is attempted on completion/cancellation; browser-session lifetime is the upper storage boundary, not a guaranteed immediate forensic wipe. |
| Transaction fields, signed raw bytes, hash, outcome and durability proof | Exact original raw/hash is saved and read back before POST; account record and per-hash history persist in `storage.local`, without vault-password encryption. The raw transaction is not a private key but can be broadcast. | Approved transaction raw bytes go to `https://evm.ynxweb4.com`; RPC returns a hash/status/proof, and the requesting DApp receives the permitted result. Chain participants/explorers may later expose transaction data. | Unknown/ACK outcomes remain recoverable. Explicit retry uses original bytes, after review/password. Remove account does not delete this journal/history. No time-based pruning is currently implemented. |
| Read-only DApp RPC request/response content | Allowlisted methods/size limits; these reads can occur without an account grant or per-read signature prompt. | Query fields and results are exchanged with the fixed RPC over HTTPS. `eth_call`, logs, storage and block reads are included in the allowlist; forwarding read methods does not enable contract transaction signing. | Stop using the requesting DApp or disable/remove the extension to stop future requests. |
| Preferences and remembered public connection | Extension-page `localStorage` contains locale/legacy theme preference and a validated public session; the public PWA uses its own origin storage/cache. | No telemetry path exports these records. | Different from the vault and journal; removing a site permission is not a browser-wide data deletion command. |
| IP and HTTP/TLS connection metadata | Generated by browser/network, not a custom analytics payload. RPC fetch omits cookies, bypasses cache and rejects redirects. | The RPC endpoint and its infrastructure receive connection metadata. Opening official website/download/explorer links sends an ordinary browser request to that destination. | Actual operators, processors, regions, logs and retention are **unconfirmed** and block final privacy-policy approval. Do not state that server logs do not exist. |

## Firefox declaration

Required manifest categories: `authenticationInfo` (authentication/authorization signatures), `financialAndPaymentInfo` (account/transaction data), `websiteContent` (DApp RPC request/response information). This mapping is an implementation-based interpretation, not a Mozilla pre-approval. The local password remains local even though authentication data is declared. No optional data is implemented; specifically no analytics/crash-reporting `technicalAndInteraction` collection is added.

`browsingActivity` is not declared as transmitted: the observed origin/tab record stays local, with no separate visited-URL upload. The code does not gather health, contact-book, personal communications, precise location, searches or bookmarks. Arbitrary DApp input is not permission to add those collection features. Reassess the manifest and consent flow before any new transmission or server-side analytics changes. [Mozilla taxonomy](https://extensionworkshop.com/documentation/develop/firefox-builtin-data-consent/)

## Chrome / Edge dashboard worksheet

Single purpose: use the listing's narrow wallet purpose. Remote code: **No** for this source; CSP permits local scripts only, and RPC returns data rather than executable code. Do not confuse a linked website or minified bundled library with remote code.

Proposed data selections for publisher review: financial/payment information; authentication information; website content; web history limited to locally used approved site URLs/origins; and personally identifiable information insofar as the dashboard includes the persistent wallet account identifier. Explain local-only vs transmission in the policy instead of selecting “no user data” because there is no analytics backend. No health information, personal communications collection, user-activity tracking, precise location collection or search/bookmark collection was found in the extension. The stores' actual current field definitions must be checked before the publisher attests; these checkboxes have not been submitted.

The publisher must confirm the Limited Use certifications against real service operation: data used only for the disclosed wallet purpose; no sale, advertising/credit profiling, unrelated transfer or routine human review. Source inspection alone cannot attest server/operator practices. [Chrome privacy fields](https://developer.chrome.com/docs/webstore/cws-dashboard-privacy), [Chrome Limited Use](https://developer.chrome.com/docs/webstore/program-policies/limited-use), [Edge privacy fields](https://learn.microsoft.com/en-us/microsoft-edge/extensions/publish/publish-extension#step-6-enter-privacy-information)
