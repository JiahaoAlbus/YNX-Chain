Write, review, recover.

Learn the document workflow and the API used by this editor. These guides can be read without connecting a wallet.

Your first document

  1. Open the editor and choose Sign in. Authorize the Docs scopes in YNX Wallet only if you agree to them. Never paste recovery words or private keys into Docs.
  2. After a Docs session is authorized, choose New document and enter a title. The document service must be available before creation can succeed.
  3. Write in the plain-text editor. Read the save status before leaving. Offline drafts stay on this device; they are not a server backup.
  4. If a newer server version exists, compare it with your draft. Keep your draft as a new document or explicitly choose the server version.
  5. Use Versions to inspect earlier versions and confirm a restore. Use Export for text, Markdown, HTML or JSON.

Comments refer to a specific version. Presence indicates recent activity, not simultaneous real-time editing. AI receives the selected document version only after consent; review its result before applying it.

When sign-in fails

A missing YNX authorization bridge can be retried after enabling YNX Wallet. A declined request can be retried voluntarily. MetaMask detection alone cannot create the private Docs authorization session. If the service fails, retry after it recovers; do not replace your credentials with sample tokens.

“Docs session authorized” describes access to Docs. It does not establish a verified standard wallet connection or a completed transaction.

Integrate without mixing sessions

The editor uses relative /api/v1 routes. Its current YNX authorization request uses product docs, client and bundle com.ynx.docs.web, callback /docs/auth/callback, and chain ynx_6423-1. This is a product-specific assertion flow, not an EIP-1193 account request.

The browser sends the approved assertion to POST /api/v1/session. Only a non-empty token returned by that service activates the local Docs session. Subsequent calls use the Authorization header. Do not put credentials in URLs, logs or shared examples.

Standard provider selection, read-only restoration and revocation integration are still pending shared Wallet integration. Do not synthesize a YNX assertion from a MetaMask account or signature.

Editor API reference

These are routes consumed by this client, not a claim that a public API deployment is available. All document access remains subject to server authorization.

MethodPath under /api/v1Purpose
POST/sessionExchange the approved product assertion for a session.
GET/objects?parentId=&q=List visible objects in a folder; q filters the title.
GET/objects?view=recentRead the recent-object view.
POST/objectsCreate a document or folder after authorization.
GET/objects/{id}Read metadata and version.
GET/objects/{id}/contentRead document content.
PATCH/objects/{id}Update metadata such as the name.
POST/objects/{id}/versions/{version}/restoreRestore as a new version after user confirmation.

Handle 401 by requiring authorization again. Handle a version conflict with a comparison and explicit recovery choice. Preserve the local draft when a network request fails.

新手入门开发者API白皮书

创建第一份文档

  1. 打开编辑器并选择登录。只有同意 Docs 请求的权限时，才在 YNX 钱包中授权。不要向 Docs 输入助记词或私钥。
  2. Docs 会话授权成功后，选择新建文档并填写标题。文档服务可用时才能成功创建。
  3. 在纯文本编辑器中写作，离开前查看保存状态。离线草稿仅保存在当前设备，不等于服务器备份。
  4. 服务器出现更新版本时，先对比草稿。可以把本地草稿另存为新文档，或明确选择服务器版本。
  5. 通过版本记录查看历史并确认恢复；导出支持文本、Markdown、HTML 和 JSON。

评论引用特定版本。在线状态反映近期活动，不代表实时共同编辑。AI 仅在你同意后接收选中的文档版本，生成结果需审阅后再应用。

登录失败怎么办

缺少 YNX 授权桥时，启用 YNX 钱包后重试。拒绝授权后可以自行再次发起。仅检测到 MetaMask 无法创建 Docs 私有授权会话。服务故障时待恢复后重试，不要使用示例令牌替代凭据。

“Docs 会话已授权”仅描述 Docs 访问权限，不代表标准钱包连接已经验证，也不代表完成交易。

区分钱包与产品会话

编辑器使用相对路径 /api/v1。当前 YNX 授权请求的产品为 docs，客户端和包标识为 com.ynx.docs.web，回调为 /docs/auth/callback，链标识为 ynx_6423-1。这是产品专属断言流程，不是 EIP-1193 账户请求。

浏览器将获批断言提交至 POST /api/v1/session。只有服务返回非空令牌后才激活本地 Docs 会话。后续请求使用 Authorization 请求头。不要将凭据放进网址、日志或共享示例。

标准 provider 选择、只读恢复及撤销仍待接入共享 Wallet 契约。不要根据 MetaMask 账户或签名自行构造 YNX 断言。
