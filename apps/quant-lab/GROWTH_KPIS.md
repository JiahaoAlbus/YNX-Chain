# Product and founder KPI framework

All metrics require real events and source/coverage timestamps. Empty usage stays
zero or unavailable; no synthetic users, rankings, testimonials, volume, returns,
or social proof are permitted.

| KPI | Definition |
| --- | --- |
| Activation | user imports/creates a versioned dataset and completes one valid OOS experiment |
| 7/30-day retention | activated user returns and completes a research/lifecycle task in the window |
| Task completion | valid experiments or approved lifecycle transitions divided by initiated tasks |
| Crash-free session | sessions without process/browser crash divided by measured sessions |
| Support load | tickets and support minutes per active user, split by severity |
| Abuse rate | blocked malicious/unauthorized attempts per active user and request |
| Provider cost | measured provider/data/compute cost per active user and completed job |
| Gross-margin candidate | disclosed revenue less directly attributable costs; never guaranteed |
| Public Testnet usage | unique Wallet-approved strategies with verified transaction/fill receipts |
| Conversion | eligible activated users who knowingly choose a paid plan |

Scale only when retention/task completion, crash-free sessions, provider cost,
support and abuse remain inside approved thresholds. Kill or redesign on failed
revoke/exit, misleading risk comprehension, negative sustainable economics,
unmanageable support/abuse, or data-right violations. Dark patterns and concealed
fees are prohibited.
