# C independent WKWebView public API boundary review

Reviewed 2026-10-31 against the local macOS 27.2 host, Xcode SDK 27.0 public headers, Apple documentation and WebKit upstream API sources. This is a source/API review, not a measured leak or a successful no-leak runtime result.

Decision: **no complete public-only no-bypass guarantee has been established for this installation. Keep `RoutedPlatformIsolationAdmission.current.permitsWebContent == false` and do not create routed WKWebViews.** The ordinary Browser is a separate product path. These local harness results cannot open a Tor/Nym mode.

Public `WKWebsiteDataStore.proxyConfigurations` exists from macOS 14/iOS 17. Its documented scope is networking in WebViews sharing that store; configuration should be set before loading, and changing it can interrupt ongoing operations. A store and proxy assignment are useful components, but this description is not runtime evidence for DNS, every auxiliary process, WebRTC/STUN/UDP, IPv6, downloads or failure transitions. [Apple data-store API](https://developer.apple.com/documentation/webkit/wkwebsitedatastore/proxyconfigurations-6g21z), [WebKit API header](https://github.com/WebKit/WebKit/blob/main/Source/WebKit/UIProcess/API/Cocoa/WKWebsiteDataStore.h).

`Network.ProxyConfiguration` supports SOCKSv5 and HTTP CONNECT. `allowFailover` defaults to false; implementations should explicitly retain false and avoid bypass/excluded-domain rules. This controls that proxy configuration, not an independently demonstrated process-wide kill switch. There is no basis here to claim that a listener being alive or curl using it proves WebKit routing. [Apple proxy configuration](https://developer.apple.com/documentation/network/proxyconfiguration), [Apple failover property](https://developer.apple.com/documentation/network/proxyconfiguration/allowfailover).

The local SDK public `WKPreferences.h` exposes no PeerConnection/ICE disable property. Upstream `_peerConnectionEnabled`, `_enumeratingAllNetworkInterfacesEnabled` and `_iceCandidateFilteringEnabled` are in `WKPreferencesPrivate.h`; C does not use those private APIs or KVC substitutes. Public camera/microphone denial does not eliminate a data-channel ICE probe: W3C describes address exposure without specific media consent. JavaScript wrappers are not an engine/network isolation proof, and page-visible candidate filtering is not packet non-emission. [Public preferences](https://github.com/WebKit/WebKit/blob/main/Source/WebKit/UIProcess/API/Cocoa/WKPreferences.h), [Private preferences location](https://github.com/WebKit/WebKit/blob/main/Source/WebKit/UIProcess/API/Cocoa/WKPreferencesPrivate.h), [W3C WebRTC privacy](https://www.w3.org/TR/webrtc/#privacy-and-security-considerations).

RFC 8828 describes direct STUN bypass risk in a proxy configuration, and forced proxying/UDP suppression as a distinct policy mode. It is a protocol requirement/context source, not evidence of this shipping WebKit's actual behavior. In particular, an IPv4 HTTP exit change cannot settle DNS, IPv6 or WebRTC results. [RFC 8828](https://www.rfc-editor.org/rfc/rfc8828.html).

`WKURLSchemeHandler` handles custom schemes. The local public `WKWebViewConfiguration.h:224` explicitly refuses registering a handler for internally handled schemes. Rewriting HTTP(S) into a custom scheme therefore is not a transparent public all-protocol browser isolation substitute. A navigation delegate is similarly a navigation policy surface; its successful decisions do not account for already running sockets, subresources or all engine networking. [Apple custom scheme API](https://developer.apple.com/documentation/webkit/wkurlschemehandler), [WebKit configuration header](https://github.com/WebKit/WebKit/blob/main/Source/WebKit/UIProcess/API/Cocoa/WKWebViewConfiguration.h).

WebKit separates UI, WebContent and Network processes. A test trace scoped only to the app executable can miss networking performed by those auxiliaries; synthetic resolver attribution must also be accounted for without capturing unrelated user DNS. [WebKit process documentation](https://webkit.org/debugging-webkit/).

The inference from these sources is limited: public proxy APIs can configure a candidate route, but the available sources and C's allowed local tests do not supply an auditable full-protocol enforcement boundary. Do not claim impossibility across all future OS designs, and do not claim this candidate leaked in an unperformed real test. A future admission needs an actual supported isolation mechanism and independent scoped capture for baseline plus killroute/Wi-Fi/sleep-wake/crash, including DNS, IPv6, UDP/STUN/WebRTC and downloads. Shared parent admission remains false until those separate gates exist.
