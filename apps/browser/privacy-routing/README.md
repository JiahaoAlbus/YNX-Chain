# Browser window-scoped privacy routing

Tor and Nym Mixnet are **disabled for web content** in this version. The menu opens an isolated blocked status window without a WKWebView, route process, target URL, persisted session, Wallet or AI connection. Ordinary Browser remains independent; its existing candidate is not made conditional on route readiness. Local private tabs govern local records and do not claim to hide source IP.

`PrivacyRouteProvider.start/status/stop` is the sole shared local lifecycle contract. `PrivacyRouteSession` fences late startup, cancellation and dropped routes, permits only HTTPS/WSS when admitted, and restores no tabs. `RoutedPlatformIsolationAdmission.current` is false with no public initializer or preference/environment switch to grant admission. Unit-test admission is an internal fixture only, never target-network acceptance. `openRoutedWindow(mode)` owns separate windows; ordinary navigation/download/Wallet/menu actions cannot operate behind the active route window. Explicit Open Ordinary Window transfers no URL.

The macOS factory configures a separate non-persistent WKWebsiteDataStore with Network SOCKSv5 `ProxyConfiguration.allowFailover=false` before WKWebView construction. That setting alone does not prove containment of DNS, WebRTC/STUN, UDP/QUIC, downloads, auxiliary WebKit processes or connection failure retries. No private KVC API or JavaScript substitute is used to claim network isolation. The production factory rejects missing admission before view creation.

Tor uses an adapter for official Arti, fixed at 2.7.0. The [official build guide](https://arti.torproject.org/guides/compiling-arti/) requires a source build and says no official binaries are provided. `tor/upstream.json` retains source checksum availability gaps. A process handle is classified `processRunningOnly`, never a bootstrapped circuit or a connected Browser route. Nym uses the official Mixnet SOCKS5 client source pinned in `nym/dependency-pin.json`, anonymous replies and domain-form SOCKS requests, with no local DNS lookup in the request encoder. Missing macOS supply or verified Mixnet readiness remains blocked. Encoding a request does not prove WKWebView routing.

The independent `leak-tests` suite uses only synthetic `.test` names and temporary local TLS material. Its local endpoints and normalized trace analysis are fixtures, not installed-product proof. Absent raw scoped capture, route/failure coverage, test install identity or target observations remains NOT_RUN/INCOMPLETE. It does not collect ordinary user browser or DNS history, change trust stores, buy services, change system proxy settings or deploy public endpoints.

Before either route is admitted independently: verify the exact signed install/platform and official source/binary pins; establish an enforceable whole-window network boundary; open two ordinary sites plus search, cross-origin resources and download; independently observe target exit traffic and client-scoped raw capture without target direct/DNS/IPv6/WebRTC leaks; test kill-during-load, WiFi switch, sleep/wake and browser crash; report first connection, later P50/P95, success rate and disabled features. These target acceptance steps have not run. An exit IP change, curl success, process/socket readiness or a settings control cannot replace them.
