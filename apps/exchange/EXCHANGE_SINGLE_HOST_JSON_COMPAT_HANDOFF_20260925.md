# Exchange single-host JSON compatibility

The Exchange server now selects process-local admission only when `YNX_EXCHANGE_DATABASE_URL` is absent. It preserves the existing persistent JSON venue, guest markets and existing authentication/idempotency paths. `/health` identifies `file_snapshot` and `multiInstance:false`; `/ready` remains HTTP 503. An explicitly configured PostgreSQL URL must connect for state and admission or startup fails, with no fallback. An absent `YNX_EXCHANGE_FINANCE_READ_KEY` leaves the separate Finance account-read route HTTP 503.

Focused Go tests cover the JSON path, guest market, readiness, disabled Finance read, second startup without rewriting state, and configured PostgreSQL failure. `go test ./apps/exchange/... ./internal/exchangeproduct/...`, `go vet`, Exchange Node 55/55, smoke and Chrome browser 3/3 passed. Browser QA now waits for DOM content rather than impossible network-idle while the market stream is active; its fallback assertion is scoped to the chooser because the page also has a legitimate Wallet download link.

This is a source-only compatibility checkpoint. It does not make JSON multi-instance-capable, migrate state to PostgreSQL, deploy Exchange, prove a real Wallet approval, place an order or settle a trade. A future PostgreSQL migration needs an explicit verified JSON backup and reconciliation of account balances, orders, fills, idempotency and audit state; setting a URL alone would start a new empty database. An Exchange-only release must re-read the current runtime and rollback target and obtain its own authorization.
