# Original contract runtime migration R1

This candidate follows the successful `aa97f102fc72ee89ef3c61b6125256b288694b39` remote baseline. It is not included in that result. Resource Market retains its separate frozen manifest. No contract migration tests have run yet.

The source stores original addresses, current storage, compiler/verifier records, ABI and historical transactions. It does not store deployed bytecode inline. Its address includes a timestamp; the BFT deployment address derives from a new signed transaction. Import must preserve the original address and current storage, without invoking a constructor or creating a BFT deployment receipt.

The first executable scope is exactly the two existing bounded registry identities, `SampleEVMWriteCounter` and `SampleYNXTCompatibleERC20`. All other contracts, missing real compiler materials, contradictory metadata, and unmapped deployer identities remain explicit blockers per address. Their complete original records remain in the source runtime.

Materials come from this source repository's fixed `artifacts/contracts` and `artifacts/build-info` roots. Both lexical paths and resolved symlinks are confined to those roots. The loader derives the artifact path from the registered name; it does not open an arbitrary path supplied by a source record. It checks actual source contents, compiler version/settings, creation/runtime bytecode, original ABI hash, source artifact commitment and independently derived function selectors. A supplied compiler label or path is insufficient.

`ContractMaterials` stores the actual artifact and build-info file bytes, shared by registered name. Byte arrays preserve the exact original ABI JSON bytes across migration JSON serialization; raw JSON fields could otherwise compact whitespace and change the source ABI hash. Limits are 1 MiB per artifact and 16 MiB per build-info file. The complete materials participate in the migration state hash. Import/restart validation is deterministic and requires no filesystem or compiler.

The live adapter retains an immutable `LegacyContracts` segment, internally anchored to the complete migration hash, and an executable contract at each original address. Old deployment metadata stays in original history. Imported contracts have no BFT deployment height or transaction. Each subsequent accepted call produces a real BFT call receipt, current storage, actual logs, fee, nonce and audit commitment. Source write-selector checks and the source's additional ERC20 transfer-result/storage checks remain enforced. Original compiler, ABI and verification metadata remain queryable at `/ide/source` and `/ide/source/<address>`; the existing verifier and static-call paths use the imported source branch. Failed calls detach candidate account and contract state before charging or execution, preserving the preceding state on rejection.

Classic Action calls continue through the existing account-policy gate. An activated PQ account cannot invoke a classic call. A PQ Action wire for contracts is not implemented in this stage and must not be replaced with classic authorization.

The source's contract-call fee field is not replayed to repair its historical accounting. The complete account checkpoint is imported exactly. Future BFT calls use the target's existing signed Action fee and nonce rules; the different historical fee bookkeeping is explicitly retained as source history.

Required acceptance: build both registered Solidity sources with the pinned normal Hardhat/Wasm pipeline and run `npm run contracts:selectors`; then test actual source deploy, source write, quiescent export, original-address import, static reads of already-mutated storage, the next real signed call, invalid selector rollback, PQ classic rejection, restart equality, missing/changed code, source metadata mutation, path traversal and symlink escape. A source-only adapter is not deployment or public cutover evidence.

Suggested focused command after the standard compiler prerequisites: `go test ./internal/chain -run 'TestConsensusContract|TestConsensusArtifact' -count=1` and `go test ./internal/consensus -run 'TestMigratedContract|TestMigratedERC20' -count=1`. The existing complete chain/API/consensus suites remain necessary for the changed persisted-state schema. Verification currently reparses shared materials during state validation; this stage makes no throughput claim and does not add an unverified fast path.
