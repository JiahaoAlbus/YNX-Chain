## Existing recipes and source-specific limitations

`scripts/ops/remote/public-bft-scoped-backup.sh` already limits archive paths and preserves transaction identity/hash. It includes `/etc/ynx`, which may contain credentials, so its archive must stay operator-private and must not be uploaded to this repository, GitHub Actions, chat or a developer workstation. The broader `scripts/ops/backup.sh` also includes other products and validator home directories; it is not a data-minimal PQ rehearsal recipe.

The existing public-bft scripts require an authoritative release named `ynx-chain-<12hex>` plus a BFT gateway release. The observed live producer instead reports `ynx-network-surgical-65efa82e0615`. Do not invent a matching release string or bypass the check; the existing operator must identify the correct original deployment recipe before using these scripts.

`public-bft-final-snapshot.sh` requires matching transaction-bound mutation-freeze and production-pause evidence. Stable block height alone is insufficient: pending admission, faucet, module writes, replication and shutdown persistence can alter state without a new block. A preliminary consistent copy can use the operator's existing filesystem snapshot facility; the final cutover copy requires the established complete writer boundary and precise in-flight/UNKNOWN reconciliation. This plan does not authorize creating/removing live markers or stopping services now.

The `ynx-chaind --export-consensus-state` process first calls the persistent constructor, which re-saves state, and applies configured options before export. It is not a read-only live-directory inspection command. Run it only against a separately writable rehearsal copy, with explicitly controlled configuration, no inherited PQ activation option, no live replication target/key and no producer/API write traffic. Never launch it beside the authoritative process against the same data directory.

The relevant ledger files are `devnet-state.json` and `devnet-state.integrity-version` beneath the actual configured data directory. These represent the full typed state above, not merely balances or block headers. Preserve the complete operator restore point, but use an approved state-only clone for code rehearsal; secret-bearing service configuration and validator signing state stay with the original operator. Existing validator signer anti-equivocation state must never be reset or restored backward to enable signing.

Authenticated replication uses a bounded batch/snapshot plus HMAC transport. Its secret remains operator-side. A raw public integrity digest is not HMAC authentication or proof of global truth. Complete histories can exceed 128 MiB; current production import bounds are 256 MiB, intermediate batch budget 64 MiB and 4096 blocks. Do not confuse the isolated benchmark's 32 MiB fixture budget with an allowable limit on original public history, and do not silently enlarge these bounds.
