# PQ protocol and existing Chain runtime integration

This source integration retains both fixed parents: protocol `8d5080e6caacdcd069ef205978e9b67e760c0a55` and existing runtime `d47b0fb8bf817093d1da0cd0dc8b08725bfae0f7`. The later protocol DEX/remote/key-init commits are applied separately. It is not a testnet activation receipt.

The existing Ethereum transfer formats, account abstraction, staking, asset authorization, DEX, fee journal, sparse native account updates, snapshot/block journals, state sync, indexer recovery and gateway proof paths remain in the source. Protocol account policy, complete PQ history, full-key consensus registry and independently pinned engine schedule remain authoritative.

## State and execution boundary

- The merged runtime reports application version 20. New base state uses version/domain 18, registry state 19, and scheduled consensus state 20. YNX-BATCH/v0.1 algorithms, signatures, trees, encodings and security parameters are unchanged.
- Historical performance domains 7–13 and protocol domains 14–17 use explicit copies of their original hash documents. Historical records cannot carry fields outside their committed domain.
- Loading a valid historical checkpoint preserves its original height, hash and history. Loading does not migrate or rewrite the file. A new state domain is persisted only through the actual new block Commit.
- The block-journal decoder binds historical deltas to the validated original checkpoint version. Its private replay mode is not a transaction field or a normal live execution mode. A version-changing live Commit writes a complete new checkpoint instead of mixing domains in a delta stream.
- Existing native ABCI transfers retain their original fee-lot movement; PQ transfers retain their existing source amount-only lot movement. These are explicit internal routes. Their balance, nonce, fee and bandwidth checks remain in force.
- Native account and fee journals remain immutable across speculative branches. PQ/account-action branches materialize and detach native deltas before accessing the shared business executors. Only the trusted cache clone shares certificate computation roots.
- State-sync restoration checks exact offered version, independent expected AppHash, original migration, policy/registry/schedule continuation and independent operator schedule. Pending data is not published as committed state.
- Account abstraction checks both the real inner account and actual paymaster sponsor against current account policy. A different outer bundler does not restore retired classic authority. A complete PQ account-abstraction message/executor is still separate work; no arbitrary Action kind is accepted.
