# Resource sponsor execution bridge, source candidate R1

This is source implementation, not a passed test or deployed migration. No Go compilation, service, node or benchmark ran in this subtask. The production source tree is `ynx-pq-public-upgrade`, rooted in public service commit `65efa82e06158f9616172144c3c9efdd8088f227`; this does not establish that the public authoritative producer already runs CometBFT.

The migration v2 complete runtime remains the source checkpoint. `LegacyResourceSponsor` is a typed immutable copy of its pool, sponsorship, idempotency, action-reference and audit inventories. Its anchor is constructed internally from the complete migration `StateHash`; an action payload cannot supply it. State validation requires exact equality with the anchor, every original pool's continued presence and identity, original-plus-new consumption coverage, original request/audit/transaction correspondence, and no new record shadowing a source idempotency key or action reference.

Original pools enter the actual `ResourcePools` collection used by `applyResourceSponsorAction`. Their original addresses, owner, policy, expiry, cumulative allowance, consumed units and account resource usage remain intact. Untouched imports have no invented BFT signer, transaction, block height or audit hash. A subsequent genuine signed fund, policy, status or consume action modifies that same pool, advances the actual signer's nonce and records native BFT metadata. Revoke releases only the remaining allowance. Fee remains zero and no YNXT transfer is manufactured.

For a source idempotency match, the current signed action is verified first, including the current account policy. The adapter then restores the original source typed request document with zero authorization and uses the original `YNX_RESOURCE_SPONSOR_REQUEST_V1` hash domain. Signer, key, action and complete normalized request must match. Matching requests return the original pool snapshot or sponsorship and original committed transaction in ABCI result `Data`; they do not consume nonce, allowance, fee or audit sequence again. Changed requests reject. Expired original requests remain readable/replayable because the historical hash helper performs no wall-clock check. New native sponsor idempotency now similarly returns its exact stored result on equal input and rejects conflicting input.

The old audit entries remain unchanged in their source domain. The first new BFT audit entry points to the source tail and continues its sequence. Existing sponsorship, idempotency, audit and action-reference query paths include anchored source records; `/resource/sponsor-source` exposes the full typed original segment. Analytics include both source and new sponsorship consumption. The immutable segment, live pools and new records are persisted and hashed in committed state version 15. Legacy version 14 hash bytes remain unchanged when new optional fields are absent.

Current classic Action authorization rejects an active PQ signer before module dispatch. Sponsorship also checks the selected pool owner's policy, preventing an unactivated beneficiary from using a newly PQ-controlled owner pool through classic authorization. A historical read-only replay by a still-classic beneficiary does not consume that pool. There is no new PQ sponsor Action wire in this candidate; active PQ users cannot use classic signatures to work around that missing transport.

The complete migration anchor is an operator-verified source checkpoint, not a proof that legacy source records contained BFT signatures. Old sponsor source snapshots preserve the authority recorded by the old producer, and this adapter does not fabricate absent historical signatures. Source records missing exact pool snapshots, transactions, audit or request coverage fail closed. Source and target resource pool policies still enforce their declared canonical types and bounds. Other module blockers (Pay, AI, Trust/governance, resource rentals and contracts) remain explicit; this adapter does not authorize an otherwise blocked full cutover.
