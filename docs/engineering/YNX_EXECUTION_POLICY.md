# YNX 全项目统一开发执行政策

生效：2026-10-18，依据本人最新直接指令。适用于全部 YNX 产品、模块、线程、子代理、负责人、暂停待办和后续新任务。与旧的仅盘点、阶段结束停等或局部范围限制冲突时，以本政策及更新的直接指令为准。

**开发不停摆，问题当场修，验证自动跑，交付落到能用。**

## 1. 每个执行单元实际落实

- 原负责人收到后立即应用，并同步自己管理的全部现有子任务；在其适用执行规范、AGENTS.md 或目标记录中保存本政策。新任务创建时默认继承。
- 政策下发、规范整理和开发并行，不能为写政策暂停正在进行的实现、构建或验收。
- 此前暂停、待办且具备推进条件的已授权任务恢复；缺少具体权限或真实依赖时仅阻断依赖动作，其他工作继续。不可把旧暂停提示或自动目标消息当成最新直接指令。
- 不创建替身、换线程或重写计划规避未解决的问题。保留现有成果、未提交修改、服务和数据。原模型设置保持，永不开快速模式。

## 2. 开发不停摆

- 按本人确认的完整目标持续实现，不能自行缩成方案、演示、接口占位或文档交付。
- 能独立开展的工作立即并行；明确每个任务的模块、文件和写入所有权，避免相互覆盖。
- 模块按固定提交和稳定接口验证，不等待全仓统一冻结；已具备条件的任务主动接续，不等用户逐项催促。
- 资源排程只处理实际冲突：重构建或持续重压测按新鲜容量控制，同一 GUI 一名操作者；不能扩大为独立源码和轻测停工。

## 3. 问题当场修

- 发现问题进入“复现—定位—修复—回归—继续开发”，保留真实反例和首因。禁止只记风险后等待审查。
- 暂不能解除时，写明负责原 owner、实际缺项、依赖任务和解除条件，同时推进不受影响的部分。
- 不用重复调查、阶段报告、换编号或新框架替代必要实现。内部缺函数、生产调用或接口合同属于 owning CODE，不能笼统算外部材料不足。

## 4. 验证自动跑

- 将适用编译、测试、静态检查、接口和关键回归接入原持续集成，随相应源码变更自动执行。
- 复用仍适用的测试、固定输入、构建和证据；只对新差量、失败或未解决问题补必要验证，不重复旧绿组。
- 必要针对性复核与独立开发并行。密码学、安全授权、数据完整性、共识一致性问题阻断受影响版本的发布或激活，不阻断无关开发。
- 不跳过验签、不删除失败测试、不降低授权、不清空真实数据来制造通过。零命中、跳过、仅编译、模拟资源和真实执行必须分别记录。
- 平台明确拒绝的具体动作保留原错误及待办，不绕过、不换入口规避；继续其他允许的研发。

## 5. 交付落到能用

- 以真实使用流程验收。源码、局部编译、接口或文档均不能单独算交付。
- 跨前后端、客户端、服务端、链和部署的任务跑通相应真实端到端流程；迁移、备份、恢复必须实际验证对应流程。
- 适用时提供可复跑源码、精确构建产物、正常运行入口、部署记录和验证结果。明确源码、测试、包、安装、部署、服务和真实业务之间的版本关系。
- 性能使用相同条件下的实际持续测量，分别报告提交、入块、最终确认、延迟及资源开销；不以理论倍数或挑选样本代替结果。
- 保全账户、余额、nonce、合约、历史、密钥、草稿、outbox、UNKNOWN、首因、撤销和回滚记录。不因常规开发授权而伪造 Root、issuer、角色或真实资金批准。
- 原发布/构建所有权和正常入口保持；未知外写先恢复原结果，不能盲重。具体即时真实资金操作仍须本人明确确认。

## 6. 总控持续落实

- 总控检查无必要等待、只审不修、只写计划、重复询问常规选择及半成品冒报；发现后直接推动原 owner 修复、解除依赖或清楚重新分配所有权。
- 常规实现选择在授权目标内自主推进。只有新增权限、改变目标或未授权不可逆动作才集中提出具体决策，其余任务继续。
- 使用四类状态：**正在实现、已实现未验证、已验证未部署、已部署可用**。补充真实在途 PID/session、提交、产物和依赖，不把分配或准备冒成执行。
- 进度只报告实际成果、当前工作、具体阻塞及距离可用还差什么；不以审查次数、报告数量或代码行数代替完成度。
- 原负责人将本政策传递到自己的实际子代理；不可只回复“已知悉”。一次简短回传实际下一动作和规范路径，之后以开发成果体现，不另开政策审查周期。
