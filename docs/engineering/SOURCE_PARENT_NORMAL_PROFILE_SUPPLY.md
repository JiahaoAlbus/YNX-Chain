# SourceParent normal postbuild profile supply

The original Core private target is `pqOriginalSourceProfile{images [3]string}` in `internal/consensus/pq_source_parent_bootstrap.go`. Order is parent process executable, Core executable, Native child executable. These independent expected pins must not be copied from v3 stdin. Core checks actual kernel process/start/UID/PPID and image bytes independently.

The new offline producer `apps/wallet-desktop/scripts/source-parent-normal-profile.mjs` captures three separately selected image/record byte pins and source commit/tree tuples, compares the complete canonical selection to an independent original, streams actual staged file hashes with nofollow/nonblock/pre-post identity checks, and emits a detached zeroarg normal **DATA** getter. PUBLIC test files are not executable images or genuine build records. This step never executes an image, launches Node, signs, registers, or treats a SHA-correct record as authority. `normalExecutionVerified` and `qualifiedRuntimeResource` stay false. It does not replace the Core getter with unqualified JSON.

Observer mapping is the actual `home` plus only the original finite application fields: migration/state/stateLayout/genesisHash/originalGenesisHash/migrationHash and complete optional schedule, runtimePlan, invoiceSchedule path/hash pairs. The original Core validator still owns real private home/key absence, config, store/layout, canonicalOwner/chain/minHeight Source BIND and original process context. No validator/signing/remote/height/proof/owner selector is added.

A final trusted runtime resource reader is still owning CODE: the actual Root/qualified normal initializer must independently authenticate this postbuild tuple and expose a read-only, once-captured same-cohort result to Core's private getter and P09's actualLaunch. Existing SDK runtime-image purposes only cover their explicit HTTP/WPR image bindings and cannot authorize this SourceParent triple. Compiling the final Core hash back into the same Core binary (or parent into parent) is circular. A detached postbuild resource must therefore remain separate and be independently qualified by the original owner; merely installing the generated DATA getter is insufficient. No new Root domain, Source bool, public provider, JSON/FD setter or bootstrap claims fallback exists here.

The SDK-side resource getter contract is defined in the adjacent machine contract. Its **admission port is NOT_SUPPLIED**, distinct from these implemented and tested build facts/typed capture functions. No Root row is filled and no actual runtime expected tuple has been fabricated. Source compilation/normal package code can continue; genuine acquisition remains gated on the real original resource reader.

New CI: `node scripts/ci/source-parent-normal-profile.mjs` runs only six new DATA controls. No Go/Native/old Source groups are run.
