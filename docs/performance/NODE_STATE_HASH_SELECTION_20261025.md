# Explicit node state hash selection

Original recovered node measurements put roughly25ms of a42ms mean business Commit inside AppHash. The cached-fee-time hash encoder and safe-byte lookup already had exact-byte, selected-application, abnormal-exit/recovery and local full-validation evidence; only the performance client could select the backend. The ABCI executable now accepts `-state-hash-encoding original-json|cached-fee-time-json`, with original-json unchanged as the default. This option is independent of frozen four-node pacing SOURCEd24e97b8d3; that requested run still uses original hash encoding.

Node selection occurs before application construction through the existing immutable ConfigureStateHashEncoding API. Unknown modes and incompatible later selection fail before state is read/written. The original persistent-layout validation order remains first. Existing run/runWithLayout/runWithDiagnostics wrappers retain the original backend. No hash domain, canonical bytes, signature, full validation, persistence, recovery or nonce rule changes.

Phase diagnostics, or explicitly selecting the candidate, emit one `YNX_ABCI_HASH_ENCODING` initialization record containing actual mode and process-wide cached attempts/errors. A failed/short evidence write refuses startup. This record does not mean a listening server, executed business work, BFT finality or later hash attempts. Real migration initialization currently records zero cached attempts in both modes; the test first exposed this fact instead of assuming selection implied executed work.

Actual fresh subprocess main/flag tests cover omitted/default, explicit original, explicit cached and unsupported choices. Unsupported transport stops before a server/socket starts. Both valid modes create exactly the same durable initialization bytes; the original parent decoder reopens them. Unsupported encoding creates no durable state or success record.

A separate fresh subprocess exercises the actual node configuration/application construction path, then performs one real signed CheckTx, FinalizeBlock and durable Commit in the same selected process. Original reports0 cached attempts; the candidate advances0→2 with zero encoder errors. Nonce replay is rejected. Final durable bytes match exactly across modes and the original parent decoder reopens both. This is application-pipeline correctness, not an independent node/network result. Existing socket/gRPC admission/durability and phase diagnostics tests passed with race detection. The original cached-fee CI step now also includes these node tests.
