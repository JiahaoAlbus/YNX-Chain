# Normal private-daemon / IDE parent Source: exact separation

This successor implements a missing fixed-purpose CODE path. It does not supply
any actual Root, role, approval, release row, private key or deployed service.
The existing PQHostCatalog purpose/registry/issuer must not be borrowed here.

## Existing producer CODE is not missing

Actual A37 source (0ae7d109f026fdd4513033ad173f9d03d05faa3c) contains
`apps/wallet-desktop/src/password-wallet-vault.mjs` calls at lines 497 and 506:
`signOriginalWalletServiceRuntimeObservation` and
`prepareOriginalWalletServiceAdmissionPublisher`. Their normal SameVault
custody/review/publication already exists. A Source enrollment or Native release
row is NOT produced by that admission catalog, and this change does not duplicate
or replace those producers.

## Actual normal Native consumer

`apps/wallet-desktop/native/original-private-service-owner.inc.mm::ServiceAcquire`
calls `YNXAuthIdentitySourceAuthority.acquireOriginalSource`, which calls
`YNXAuthIdentityCurrentOwner.acquireOriginalAdministrationProfile`.
It holds the running bundle's **Resources/original-auth-identity** directory,
`profile.original` and `head.original`; SourceAuthority loads `root.original`
and `enrollment.original` from the SAME bundle and binds a compiled
`NativeSourceRelease` by the original authenticated sourceId. It independently
holds/verifies Node/verifier images, whole runtime closure and four NativeNode
registered roles before returning a selection.

The normal daemon requires originalServiceRole=`original-private-daemon`,
expectedRequest.service=`wallet-product-session-v2`, exact gateway origin,
and original sourceSelection/receiptSelection/association dictionaries.
These belong in its independently authenticated profile, not in renderer JSON.
The normal verifier's existing signatureContract purpose is
**AUTH-IDENTITY-RECEIVE**; `wallet-product-session-v2` is its service field, not
a replacement signing purpose. The existing non-catalog schema retains
productId=developer, platform=macos and
applicationId=com.ynxweb4.developer.testnetpreview. This patch does not silently
rewrite that established consumer association as the daemon executable identity.

IDE parent uses its existing independently protected Developer Source registry
at `/Library/Application Support/YNX/OriginalAuthIdentity/UID-<kernel UID>/Developer`
with its existing consumer/parent custody. It must have its own admitted
profile/selection and current binding; it cannot inherit the daemon role or
Wallet/PQHostCatalog registry. No external Node may impersonate a Wallet parent.

## Missing CODE fixed by R248

R243r2/SDK38 `loadOriginalAuthSourceIssuanceService` ->
`loadReleaseSelectedOriginalSourceIssuanceV2` ->
`OriginalSourceIssuanceV2Kernel.issueSelected/assertOriginalCompletion` was
implemented only for `wallet-pq-host-catalog-source-v1`. It could not produce
normal RECEIVE enrollment/profile originals even with independently valid
normal custody and approvals.

This one-leaf successor permits ONLY the two fixed existing Source purposes:
PQHostCatalog and AUTH-IDENTITY-RECEIVE. Root/body/selected policy must have the
SAME purpose; exact independently approved body/message digests and protected
roleKeys still bind each single N1 operation. It never uses currentKeys for
Root/profile, opens a generic signing API, creates a service or supplies a
release registration. Existing root/profile verifier schemas are reused.
The existing normal administrative CLI selects no caller JSON/ENV/arguments.
The existing empty release-selection still fails closed.

## Real release/custody inputs still absent, with trusted source required

1. **Independent root.original**: canonical existing v2 six-field descriptor
   (version, algorithmVersion, purpose, rootId, networkId, rootOwner) plus its
   independently admitted exact digest. The actual registered Root owner and
   both PQ keys must be authenticated by the accepted NativeNode observation.
   A candidate RPC account or a local signature is not the authority to choose
   that trust root. No actual values are generated by this delivery.
2. **enrollment.original**: actual Root-role AUTH-SOURCE-ENROLLMENT N1 over the
   existing frame/body; separate profileOwner and currentOwner, exact normal
   service/application/registry/endpoint/SPKI/operations/state path and original
   bounded validity. Its exact hash must be independently released.
3. **profile.original**: actual separate profile-role AUTH-SOURCE-PROFILE N1
   binding the SAME enrollment digest and independently reviewed normal
   private-daemon OR IDE-parent selection/association/instance/generation,
   exact original frames, permissions and time bounds. PUBLIC fixture selection
   dictionaries are not usable production originals.
4. **head.original and HTTP current**: actual current-role delegated by that
   enrollment. Existing `OriginalAuthSourceCurrentV2Kernel.transition` signs and
   durably journals the protected admin-selected head; `current` produces only
   nonce-bound observations of an already active original row. Initialization
   does not invent a first transition. A real protected administration decision
   and its original state/receipt are required; HTTP is NOT a mutation API.
5. **NativeSourceRelease**: independently approved typed build row in
   `native/original-auth-identity-native-release.h`, via the original private
   `YNX_ORIGINAL_NATIVE_SOURCE_RELEASE_ROWS` compile input. Required public
   fields: sourceId, root/enrollment digests, exact verifier and Node paths/
   image digests, endpoint/SPKI, purpose and three distinct original frames;
   v2 also requires proofContract/dispatch/runtime-manifest digests and exact
   NativeNode origin/SPKI/nativeChainId. Optional purpose-specific fields do
   not qualify themselves by being nonempty. No runtime ENV/JSON row setter.
6. **Backend release selection/custody**: original
   `src/original-auth-identity-source-current.js::admittedSourceServices` must
   bind the same sourceId, policy, public-original refs, node, each profile
   path/hash, and independently provisioned `currentKeys.A/B` FD refs. The
   fixed loader uses existing native dual-PQ import and native dirfd journal;
   key refs require exact path/dev/inode/uid/gid/mode/bytes/hash, no symlink,
   protected parents, same effective UID and 0600/single link. Do not send key
   contents to Root/Main or put them in a public handoff.
7. **Issuance custody/approval**: independent
   `admittedSourceIssuance` release entry for the exact normal operation, with
   separate lawful root/profile roleKeys and the separately approved protected
   approval ORIGINAL (exact message/body/purpose/role/network/owner/revision/
   validity, root-owned pinned file refs). It is not a SameVault login approval,
   PQHostCatalog approval, SSO session, caller bool or current-role key alias.
   No actual custody or independent approval is supplied here.

## Existing normal HTTP caller and configuration truth

`scripts/ynx-wallet-gatewayd.mjs` already loads
`loadOriginalAuthSourceCurrentService` and preserves partial/first cleanup errors.
Its existing normal source route uses
`openOriginalAuthSourceCurrentRequest` (also the ProductSessionGatewayNodeHost
normal physical server caller), with original request ownership, final same
Source completion and physical response fences. Actual request is ONLY:
`GET https://wallet-auth.ynxweb4.com/v1/auth-identity/source-current?profile=<exact SHA256>&nonce=<new original 32B base64url>`.
The original pinned TLS transport and before/after same-height NativeNode
observations remain required. Do not invent a profile or replay a nonce to probe.

SDK38 source has `admittedSourceServices=[]` and
`admittedSourceIssuance=[]`; this identifies this candidate SOURCE configuration,
not the deployed public server's build or state. The observed bare GET 405
without nonce/profile cannot prove absence of a deployed issuer/Source.
No network request, SSH, current signing, activation or restart was performed.

Actual A37 SDK intake independently records all four normal bundle originals
absent and no NativeSourceRelease macro in recorded Node/helper argv. The generic
header defaults to an empty vector. These are precise candidate release/config
gaps, not evidence that publisher CODE or every deployed Source does not exist.
IDE startupSelection null remains unqualified; no Root or login grant is forged
to fill it. A real admitted normal Source handoff needs the public fields above,
their original approving/provisioning provenance and the matching build/runtime
receipts; only protected custodians retain the corresponding private references.
