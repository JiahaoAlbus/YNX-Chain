# Source-only canonical successor to Auth22

This branch integrates original Auth R191 HTTP-principal methods plus the frozen R193 normal Host HTTP relay and observation-only recheck and the fixed R194 project-control DATA codec, including exact R183/R189 relative imports. It is not a new published package or an updated installed client. Auth22's package version is retained only as the frozen source base; no Auth22 tarball is republished from this branch.

The existing Node-only service consumer is `ProductSessionGatewayNodeHost.authenticateOriginalDeveloperHTTPRequest` followed internally by the genuine credential consumer, or `currentExistingDeveloperPrincipal` for the combined operation. Both use the original durable Product Session Host. The credential is an in-process reference, not JSON. The principal result remains DATA, with `authorized:false` and `nativeAdmission:false`. No renderer factory, credential mint or new public control API is added.

R194 fixes noncanonical base64url member aliases. Its codec remains an internal relative import for Auth's original Native/current-capture consumer. It does not itself authorize project control. The supplier PUBLIC AND tests are persisted in the original CI alongside the new SDK consumer/type/intake checks. Existing prior green groups are not rerun locally.

## Unfinished admission and delivery gates

- R193 mounts the normal POST `/v1/developer/original-http-principal` authenticate/recheck handler in the original Host. The separate approval route remains unqualified. Deployment, independent TLS/SPKI admission and genuine Root-selected Source commissioning remain pending; this is not a live issuer. Auth owns the Go adapter, which is not copied into this SDK branch.
- Complete publication approval requires the matching publication-purpose verifier and fixed CLI/dispatch closure. Import availability does not qualify that workflow.
- The new Source IO `openV2Existing` requires the matching original A build. The previous SDK22 Node26 IO artifact cannot qualify it.
- The two new Native control selectors and their matching full build remain pending formal freeze and A intake. No stub or fallback is supplied here.
- Root-signed Source provisioning, actual user authorization, installed Wallet/IDE login, session recovery and revocation are not verified by these source tests.
- The existing Main61e3/Auth20 DMG normal attach refusal remains unchanged. No alternate mount/install path or account/data clearing is authorized by this source integration.

Accounts, existing state and UNKNOWN effects must remain intact. Future original issuer/native intake must reconcile the original request/result before any retry.

R193 integration retains the R191 authenticate path and adds `revalidateOriginalDeveloperHTTPRequest` and `recheckExistingDeveloperPrincipal`. Recheck requires the original consumed proof and revalidates current/revoke without replay-ledger writes or nonce rearming. Combined principal methods require genuine Source brand/purpose before proof consumption. Only the two newly supplied R193 cases are selected in the successor CI; the prior nine and Go groups are reused. R196 Native selectors are supplied separately and require a further matching source intake.
