# Migration compatibility — Candidate

Existing first-party callers keep the registered Product Session route and may migrate only known legacy callbacks through the shared registry migration. Unknown legacy schemes fail closed. External EVM DApps use Layer A directly and receive no `ynx1` address or YNX private scope.

Shop Android retirement requires an Integration-accepted active identity and a separately recorded retired client/package/bundle tuple. The exact-digest registry/state transaction must disable every retired callback and App Link, revoke its sessions, approvals and device grants, and preserve the supported Shop client. No client is retired merely because this protocol capability exists.

The authoritative product progress record is `integration/product-migration-matrix-v2.json`. Social, Pay, Shop, Exchange, Quant, Developer, Video, Creator Studio, Calendar, Finance, DEX and Card are listed exactly once. `PROTOCOL_ONLY` and `NO_EVIDENCE` are intentionally not migration completion. Only direct per-platform evidence for all eight required scenarios can produce `MIGRATED`.
