# WPR1 public materialization DATA

Purpose `wallet-native-product-source-v1`, selection `walletNativeProductV1`.
This is a build-only DATA inspector and immutable public-original manifest emitter,
not a signer, Source constructor, Root registration, publication receiver, install
or service activation. Default reviewed selection is the private empty constant
in `src/original-wallet-product-materializer-data.js`. The normal zero-argument
command is `node packages/wallet-auth/scripts/ynx-wallet-product-public-materialize.mjs`.
It refuses `WPR_REVIEWED_PUBLIC_ORIGINAL_LOAN_NOT_SUPPLIED` before opening any
path/key. Arguments, ENV, received JSON, providers or ordinary objects cannot add
an admitted row. The DATA function is intentionally usable by PUBLIC controls;
its result is never accepted as a Native loan or approval.

The original `loadOriginalAuthSourceIssuanceService` path would eventually call
`src/original-auth-source-issuance-v2.js:loadReleaseSelectedOriginalSourceIssuanceV2`
and initialize `entry.roleKeys.A/B`, then `importKeyMaterial`. The original current
loader similarly initializes currentKeys. Neither is imported or invoked by the
new materializer. The one independent administrative approval validator is
extracted verbatim into `original-auth-source-issuance-approval-data.js`; the real
issuer imports and calls that same function. Existing role-key/current custody,
N1 signer, dirfd journal and `scripts/ynx-auth-source-issue.mjs` are preserved.
No new signer or signing route exists.

`materializeOriginalWalletProductPublicDATA` consumes exact8 independently held
inputs: original5, independent policy, acquisition/fresh registered4 role views,
current context, approval2, build metadata, independent exact16 build canonical
original and actual build-original6 bytes. Root/enrollment/profile/current math
uses the original verifier functions; the historical head is rollback baseline,
not fresh authority. Fresh nonce and prior sequence/floor/head/time/execution
height are independent. Role views retain the original registration parser brand;
cloning JSON does not preserve this brand. Both exact issuance approvals bind the
existing E8 message and body SHA/role/owner/network/keyVersion/window. Full Source
permissions and fresh current remain an independent Native check before effects.

The emitted immutable strings contain the public4 Root/enrollment/profile/
acquisitionHead, their pins and a separate fresh-current observation. The static
WPR3 exact16 tuple is sourceId/signatureContract/root/enrollment/verifier/node/
runtime/endpoint/spki/nativeNode/applicationId/productId/platform/uid/
resourceDirectory plus version. UID is u32 number, proofContract is the existing
`YNX-AUTH-IDENTITY-PROOF-DATA/v1`. Dynamic fresh nonce/head bytes are NOT pinned into
a compiler header. WPR3 remains the sole static file/runtime manifest/15-closure-
group inspector and header generator; WPR1 binds its independent tuple and six
actual original byte pins, not every runtime leaf. WPR3 must inspect all manifest
leaf bytes before compiling. No stale runtime/Node/App qualification is inherited.
