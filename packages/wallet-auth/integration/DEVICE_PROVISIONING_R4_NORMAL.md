# Matching original provisioning Source

The original SDK private fixed-image module now supplies
`acquireOriginalProductSessionDeviceV4ProvisioningSourceStage()` with zero inputs.
Main owns the normal controller and genuine approval peer. Capture an original
failure's partial before interpreting it; retain entered outcomes and drain
child retire/join/close before parent. UNKNOWN keeps its original operation and
journal; it never authorizes another key generation or registration retry.

The explicit normal build command is:

```
node apps/wallet-desktop/scripts/build-original-auth-identity-native.mjs device-v4-provisioning arm64 /absolute/node-headers /absolute/ecdf-typed /absolute/ecdf-creator
```

Append `--plan` to validate the same inputs and emit the exact command plan
without running a compiler. Both modes reject existing outputs. The new mode
uses the original Auth plan, one pinned ecdf archive, owned undefined-symbol
scan, and all four required HTTP/typed/creator exports. Old pending profiles
remain separate. The SDK raw Node body is not Main's Electron Node body.

R4 Source/NAPI, fixed Main module, and official Core components retain their
original owners. Source release enrollment, account approval, asynchronous
registration, cold query selection, matching installed App and actual user
login/restore/revocation remain independent acceptance gates. Source graph or
build-plan validation does not establish any of these effects.
