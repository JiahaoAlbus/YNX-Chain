# Auth8 integration boundaries

Auth8 adds the original Protocol artifact publisher R13/M framing, R159 exact manifest DATA, the Native contract Relay guard consumer, and a build-time WalletConnect dependency inventory. It does not modify the frozen Auth6/R155 or Auth7/R159 packages.

The publisher key is purpose-isolated and uses the original portable dual-AND primitive and KEY-MATERIAL/v1 ABI. The protected Main store is its only intended custody consumer. PublicOriginal R binds the original network/owner, account/project/publisher, independent publisherKeyVersion and both public keys. A signature binds the full retained R and exact canonical manifest bytes. Inspection proves mathematical DATA only: it does not prove current Source identity, registration, ACL, approval, expiry or revocation. Auth must recheck its real current Source and registered publisher before and after the actual effect. Keys and signatures in tests are public ephemeral fixtures, never user accounts.

The dedicated developer contract connection now requires an opaque result from `acquireOriginalIDEContractRelayGuard` and the matching `relayContext` (projectId, positive-safe-integer projectGeneration, callerIdentity). Construction is inert; initialization without the original Native producer fails before the client factory. Dedicated initialize returns void rather than exposing raw SignClient. Native current checks fence initialize/restore/connect/request and late results; native revocation preserves UNKNOWN and original correlation. Cancel/revoke/retire/join/close uncertain results retain the owner and first cause, without replay. The fixed Node addon is the sole production acquisition path; no provider or module path override is exported.

The original Native producer is not shipped by this source change. Locked WalletConnect 2.23.10 may fetch Verify public-key/attestation GET routes in addition to the fixed Relay. Telemetry is disabled for this profile, but this is not a platform egress enforcement mechanism. Actual Native/platform outbound scope and its formal producer remain required for live qualification; old product-session-v2 grants do not qualify the contract connection.

The WalletConnect closure collector inventories the whole production dependency graph with nested versions preserved. It is additive to the exact Auth runtime manifest and independent PQ candidate role, never a replacement or another SDK installation. Normal IDE/App owners must stage and verify the complete matching tuple. Source tests, import-only probes, CI packages and component builds are separate from installed login, session recovery and revocation acceptance.

Auth9 preserves the frozen Auth8 CI archive but supersedes its publisher text predicate using the now-delivered original Go codec: R catalog fields reject all ASCII <=32 and DEL, including interior spaces, while legitimate interior Unicode format characters are preserved. The R159 manifest rule remains separate and unchanged. A real RED for the prior mismatch is retained; only this differential and the new deployment material builder require additional focused validation.

`preparePQContractDeploymentMaterialData` supplies the original Go commitments for the exact two fourth-handoff contract materials. It preserves raw artifact/build bytes and requires one explicitly supplied canonical U64 constructor argument; no default test argument, nonce, owner, approval, network or sender is created. Unknown or changed materials fail. The signed source hash is the original Go NUL-delimited domain hash, distinct from the raw source file SHA256. This DATA still requires original compiler/Native validation and current user approval.
