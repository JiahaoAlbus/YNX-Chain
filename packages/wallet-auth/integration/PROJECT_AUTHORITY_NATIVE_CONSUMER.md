# Original project authority Native consumer

Auth17 consumes the frozen R171 eight-leaf successor against Auth16 source.
The existing SourceAuthority translation unit includes the new data header and
source include in both normal Node and helper closures. Node remains 13 TUs and
helper remains 11. R172's main-thread registration fence and R170's typed
publication constructor stay intact. Use the full source tar and inventory for
the normal Native build; an npm archive alone is not that source closure.

The delivered interface is private ObjC:

```objc
+ (instancetype)acquireOriginalIDEProjectAuthoritySource:(NSError **)error;
- (NSDictionary *)copyOriginalIDECurrentProject:(NSString *)projectID error:(NSError **)error;
- (NSDictionary *)copyOriginalIDECurrentPublisher:(NSString *)publisherID forProject:(NSString *)projectID error:(NSError **)error;
```

Adopt the actual Source owner before checking an accompanying error or status.
Retain it independently from the protected keycall Source through effect cleanup.
The original lifecycle is assertCurrent/retire/join/close; partials and UNKNOWN
cannot be discarded, refreshed into a new approval window or silently retried.

The independent purpose and service are `ide-project-authority-v1`, under the
fixed actual UID project-authority namespace. Its endpoint/SPKI must match the
independently compiled private release and signed Source selection. Root/release
rows remain empty by default. A caller cannot supply a path, Root, role or
registeredRef to create this authority.

CurrentProject returns a private Native principal/project snapshot. CurrentPublisher
also returns the actual original R13 NSData and original registration reference
and revision. The R13 publisher key/version is independent from the native account
signer/revision. A hash, local project UUID, Relay scope or AI admittedProject is
not a replacement for the canonical project/publisher or original R13 bytes.
A project without a publisher can be readable without creating a publisher role.

Use actual current checks and the original fixed expiry around sensitive use.
The returned expiry is the intersection of signed principal/project/publisher
and authenticated Source-current deadlines, not permission to extend an existing
review, proof or uncertain operation. Getters do not perform RPC or renew Source.

The Auth17 public Node export `original-ide-admission` retains its four typed
artifact/publication calls. That delivery added no public JS/NAPI CurrentProject
factory, openPublication factory or renderer actor DTO. The Source-v2 declaration
only describes the service/operation DATA accepted by the original verifier;
types themselves do not bind a purpose or establish authorization.

## Auth18 original opaque reader

Auth18 includes the frozen R174 normal NAPI bridge, through that same fixed
Node-only SDK export. It adds exactly these original callbacks:

```text
acquireOriginalIDEProjectAuthority()
readOriginalIDECurrentProject(actualRef, projectID)
readOriginalIDECurrentPublisher(actualRef, projectID, publisherID)
closeOriginalIDEProjectAuthority(actualRef)
```

Acquire accepts no caller Source, Root, endpoint or permissions. Adopt the actual
same-environment tagged reference before reading; a partial remains closable.
The reader returns ordinary frozen Native snapshot records, with an independent
Uint8Array copy of the actual R13 bytes. These are DATA, without additional JS
authorized/dataOnly fields or a signing capability. IDs are comparison operands
for the intended canonical project/publisher; a local UUID or AI lease cannot
replace their original provenance or the reader's independent Source checks.

Close returns undefined on actual success. Preserve the first UNKNOWN cleanup
failure and do not retry or treat it as true. SDK wrappers return original refs,
snapshots and failures unchanged, without reading, renewing, auto-closing or
manufacturing a second Source. The Native reader performs its original current
and final snapshot checks; no extra refresh follows its final comparison.

Auth's HTTP OriginalSource/principal/publication/selector issuer and
getDeploymentRequestHeaders are still separate, undelivered producer interfaces.
The backend must derive protected snapshots from the genuine original registry
and perform CurrentProject/CurrentPublisher/RecheckPermit, not trust signed
metadata or this private dictionary as an HTTP bearer. Main still owns explicit
review, its protected store and once-only effect. Matching A builds, independent
Root/platform/FD admission and actual installed workflows remain separate gates.

## Auth19 workspace-bound canonical selection

Auth19 adds the R177 original workspace selector to the same fixed Node-only
`@ynx-chain/wallet-auth/original-ide-admission` entry. It retains Auth18's four
project reader callbacks and the independent publication artifact callbacks.

- `acquireOriginalIDEWorkspaceProjectSelection(workspaceCanonicalAbsolutePath, profileCanonicalAbsolutePath, localProjectID)` takes exactly three primitive strings and returns the same opaque Native owner or partial. Unavailable module/callee returns null; actual exceptions are preserved.
- `readOriginalIDEWorkspaceProjectSelection(ref)` returns the original frozen `{projectId, publisherId, projectRevision, catalogRevision, expiresMS}`. `publisherId` may be null; revisions are canonical unsigned decimal strings.
- `closeOriginalIDEWorkspaceProjectSelection(ref)` returns the actual cleanup result, undefined on success. Each owner has independent cleanup custody; a failed/UNKNOWN cleanup is not retried automatically.

The normal IDE server supplies its actual canonical workspace/profile paths and
local project ID from its launch context, never a caller-chosen canonical ID.
Native holds the actual directory FDs and checks the original signed mapping,
kernel process tuple, path identity and current Source. Ordinary child-file
writes do not invalidate a directory. A profile must be private and owned by the
actual UID. The selector remains separate from the project authority reference.
Read its original canonical IDs, then use the same-package project/publisher
readers with those IDs. Retain and reread the selector before and after sensitive
preparation and at the actual effect; compare the fixed mapping without silent
reacquisition, renewal or publication retry. A null publisher creates no key.

This mapping is independently signed `selection.projectSelection` in the original
project-authority purpose. Legacy R171 query-only profiles remain readable but
cannot supply the new selector. No Root, release row, registry entry or mapping
was registered by this code delivery. A selector is DATA, not HTTP proof, an
OriginalSource server factory, signing approval or KEY7 access. Real login,
restore, revocation and matching App acceptance remain separate gates.

## Auth20 distinct publication result DATA

Auth20 combines the original R181 peer result transport with the existing CLI
artifact DATA verifier and fixed Main-only registration hook. The base addon
still uses 13 translation units; helper uses 11. Main's binding/include, private
review/once/signature implementation and their input pins remain a separate
Main product profile. No Main include is selected by merely being present.

The original peer instance adds `receiveOriginalArtifactReturn()` for one
publication terminal. Its success is exactly the frozen ten-field DATA result:
`decision:'publication-result'`, `requestId`,
`requestPurpose:'AUTH-PROTECTED-KEY-CALL'`, `purpose:'ARTIFACT-RELEASE'`,
`resultOriginal:Uint8Array`, `dataOnly:true`, `signatureVerified:false`,
`publicationAuthorized:false`, `nativeAdmission:false`, `approvalCurrent:false`.
The original reject shape is retained; cancellation rejects with its original
cause. It never accepts proof2 as a publication fallback. Ordinary identity
`receiveReturn()` routes remain distinct.

The private lifecycle kernel supplies `beginPublication(manifestOriginal)` and
`waitForPublicationResult()` for the actual original publication request/peer
owners. The first uses the existing exact six-field manifest validator and the
original keyCall request route. The second captures and copies the original
DATA before post-current checks and keeps terminal selection and UNKNOWN when
current/cancellation/cleanup fails. It never calls `completeProof`, `invoke` or a
second effect. Neither method constructs a Native owner or recognizes an
arbitrary object as admission. Original fixed acquisition/opaque custody remains
mandatory; PUBLIC kernel tests are not that acquisition.

The canonical eleven-field result envelope binds the original request,
invocation and manifest, the actual public publisher/signature bytes, and Main
reference/registration/revision/key-version DATA. Parsing that envelope does not
verify a publisher or approve a release. Before higher use, independent current
registered R13 bytes, original dual-AND signature verification and the actual
Main approval holder/current/revoke checks remain required. Packet-carried R13
or a reference is not its own trust source. No Linux HTTP OriginalSource or
server approval is minted by a macOS peer return. Installed Source, matching
products, real login/recovery/revocation and publication acceptance are unverified.

### Auth21 R185 original Source-current v2 producer

The normal Source-current loader and fixed GET handler are asynchronous. Both gatewayd startup/routing and ProductSessionGatewayNodeHost await their original result and retain the original partial cleanup owner on failure. The release selector remains empty until independently commissioned; this package does not create a Source, Principal, Root, signer or permission.

The private v2 producer requires the exact server Node 26.7.0 / OpenSSL 3.6.4 native signing runtime before protected private reads. Existing client Node24/Electron42 evidence is independent and does not establish server signing qualification. There is no portable production fallback. PUBLIC mathematical fixtures do not qualify production custody.

The explicit Source-current IO component has a separate input selection and one translation unit. Its new fixed openV2 mode bounds records to 393216 bytes; legacy open remains bounded to 8192. The normal addon retains 13 translation units and the helper 11. The normal 87 source inputs and the extended Source-current IO input closure are reported separately. Original A retains matching component/App build ownership.

R185 does not issue R176 HTTP-read proofs or complete the Source13 factory. The R183 Go Principal DATA codec is not yet required by a production HTTP scope caller in this package and is not used as a fabricated authority. Real login, persisted recovery, revocation, independent enrollment and actual service activation remain separate acceptance gates.

### Auth22 R186 failed-sign attempt custody

Auth21 is retained as frozen source evidence and has a known failed-sign partial-result defect. Auth22 replaces only the formal R185 producer leaf: before invoking the protected signer, it records this exact nonce/profile/body as SIGN_SELECTED; only a complete new signature becomes SIGNED. A failed attempt cannot expose a previous successful currentRaw as its own partial. UNKNOWN and the first cause remain unresolved and do not authorize signing again. Native source and the independent IO implementation are unchanged from Auth21; complete successors still require precise source/runtime pins.
