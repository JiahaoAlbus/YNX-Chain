# R37 transport retirement and original client cleanup

framer.retireTransport(cause) stops/poisons byte transport and business promises. It retains the original first cause, row/global UNKNOWN and no replay, but does not retire the actual Native client. framer current and new business calls refuse after transport stop. original.readTerminalCustody remains subject to the actual Native/source current and original complete row/once-only checks.

The existing IDE receiver must register the entire R88 dispatch + failure diagnosis as one entered lifecycle borrow before dispatch. On transport failure, stop transport first, allow that already entered same-original diagnostic to finish while current, then original.retire/join/close. Native cleanup cannot be ordered by microtask timing. No new original/provider wrapper, Source, socket, grant, post-retire read or global UNKNOWN clear is created.

New source tests are added to the normal owned-interface CI entry. Until that candidate's execution results exist, this particular changed lifetime path is implemented but unverified. Frozen SDK3.6 is unchanged.
