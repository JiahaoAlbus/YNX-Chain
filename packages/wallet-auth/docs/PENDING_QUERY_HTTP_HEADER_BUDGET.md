# Original pending-query transport budget

Both actual Node daemon Server constructors use maxHeaderSize 147456. A private pre-admission listener permits the enlarged proof only for exact POST /v4/product-pairs/original-query, with the original fixed x-ynx-product-pair-original-query-proof-v1 raw value at most 131072 bytes, remaining headers at most 16384, and all headers plus original request line at most 147456. Other methods/routes retain a conservative 16384 total including the original request line. URL normalization or a query suffix cannot select the exception. Duplicate raw proof fields are rejected case-insensitively before admission, even for other routes.

Each real server property maxHeadersCount is set to finite 36864, derived from the parser byte cap and minimum four-byte header line. This preserves all original raw headers rather than Node's default 2000-field truncation. It is a server property, not an ignored createServer option. Rejections are HTTP 431, close the connection and produce no admission/business effect. The original Auth handler's proof decoding, duplicate checks, Root/current and registered math remain required and unchanged.

The helper mirrors the exact fixed E13 transport name and cap without importing an in-progress E13 codec. It adds no encoding, alternate proof, Source, listener registration or provider API. After the sole E13 frozen source arrives, the parent must cross-check the fixed constant in the matching package.

Tests evaluate the exact two production constructor expressions, the Host's exact wrapped listener expression and each real maxHeadersCount property assignment, with PUBLIC admission/handler doubles and the real Node HTTP parser over 127.0.0.1:0. Old bb56 constructors reproducibly return 431 for a 20000-byte proof. New controls cover 24 actual requests across both constructors, including exact 131072 proof acceptance, excess proof, other headers, mixed-case duplicate, duplicate after 2100 other fields, foreign route, long target, method/suffix and parser-total refusal. All rejected cases produce zero admission/business effects. This is transport acceptance, not proof authentication, Native/Root/Source admission, production daemon execution or public proxy/TLS-intermediary budget verification.
