# Wallet mobile qualified Source contract V1

This is a Node-only reference DATA contract and portable machine-vector supply. Hermes/iOS/Android do not load Node modules. Native implements the same finite grammar using existing Source18/E8/N1 math, not a new signing algorithm or a JavaScript authority bridge.

Purpose `wallet-mobile-qualified-source-v1`, selection `walletMobileQualifiedV1`, exact operation selected by mode: 1 `mobile.transaction`, 2 `mobile.registered-restore`, 3 `mobile.original-query`. Existing desktop Product invoice14 and device HTTP GET scopes cannot grant these effects. No old purpose or wire changes.

The scope exact8 is `version,mode,reference,originalOperationID,context,originals,issuedAtMs,expiresAtMs`. Version is string `1`. reference is printable ASCII1..128 lookup only. The original operation is retained from the real durable native journal. Context exact12 is listed in MOBILE_QUALIFICATION_ABI.json. Platform is ios/android, app identity is independently Root-selected, never a guessed actual AppID. Chain/vault/key/height are canonical u64 decimal strings, with executionHeight allowing zero syntax only; historical/current registration policy remains the independent verifier's gate. Nonce and original spending-budget digest must come from the protected review/capture, not current wallclock or JS arguments. Scope <=120s is a maximum, not permission to extend any Root/current/review deadline. Current and protected clock are separate Native inputs.

Each of the existing seven Originals byte vectors is bound by exact byte length and SHA256. There is no replacement binding/review/transaction wire codec: their internal Native grammar, actual UI approval and native request/body/budget semantics still need the real Auth qualifier. Hash equality and a structurally correct scope are not an approval or Source grant. Core math does not implement that producer. Review bytes max2MiB, policy max8MiB, backup max192KiB, binding/message max8KiB follow actual r4 bounds; only digests enter signed scope, never credentials/private keys/43-byte material/DER/Member across Hermes. The independent registered context must match actual fullpair/current, ordinary owner and encrypted original. Different counter classes must not be substituted.

The reference functions capture a hidden owned copy, preserve full-u64s, compare independent selection and every original byte, and check finite phase/flag consistency. The independentSelection parameter is a DATA testing/encoding input; supplying a plain object never creates Native authority. Runtime control remains sameNativeThread and Auth's own opaque QualifiedOriginal. No public provider/options factory is exported.

FULL Source role bodies are encoded by the sole encodeOriginalAuthSourceStatementV2 and canonicalOriginalAuthSourceEnvelopeV2. The adapter does not sign an isolated scope as a replacement profile. A profile must place this scope in `selection.walletMobileQualifiedV1` and subjectOwner must equal its canonical account. Root policy supplies each frame; PUBLIC frame strings in vectors are not production defaults. Existing E8 domain/8-field framing, AUTH-SOURCE-ENROLLMENT/PROFILE/CURRENT certificate purposes, registered dual N1 math and roles remain unchanged. New family semantic admission is not registered in common5 in this handoff; native/mobile qualifier and genuine Root/current registration resources are not supplied by passing DATA controls.

Mode1 review/current/once precede sign and submit separately. SIGN_ENTERED, lost ACK or SUBMIT_ENTERED must retain UNKNOWN and original operation, never re-sign/re-submit. Mode2 only restores the already registered original backup with the actual original ordinary owner's exact binding: strict EMPTY -> matching terminal slot. RESTORED_ACK must use restoredCurrent, not require EMPTY again. No clearing an occupied slot, open_initial, new keys or new account. Mode3 never borrow43/sign/submit/restore; it only queries the same operation/OS journal. Native copy_public of an already retained original may remain readable after lock/retire/failure; it does not reauthorize query IO or renew any deadline.

Initial captured Root4 and genuine fresh current are different. Native must independently reverify Root/account/revocation/registered fullpair/window/current at each operation boundary. Do not demand future fresh-current nonce bytes equal an initial capture, and do not treat initial hashes as fresh authorization. Every partial source/loan/OS child is adopted before interpreting status, on the same native thread. Original outcome/first cause is retained before late-current failure. Drain loans and effect/ACK debts before parent release; close status does not prove cleanup. No actual Native/Root/device/transaction verification has been performed here.

Normal integration: add this module and declaration to SDK's existing native reference inventory, with Node-only private/reference export if needed. Browser/default/mobile JS authority exports remain absent. Parent owns package/SourceGit changes; Auth owns real qualifier, OS slots, policy selection and UI. Read MOBILE_QUALIFICATION_ABI.json before implementation. The portable CI entry is scripts/ci/wallet-mobile-qualified-source.mjs; it only runs new controls and strict declarations, never a native build or real signing resource.
