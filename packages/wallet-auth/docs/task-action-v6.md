# AI task action V6 DATA and mathematical proof

This is the new V6 profile authorized by the sole SDK/Root owner. It preserves V4 read and V5 IDE bytes and does not register a native application or authorize a task. The baseline atomic field/frame contract is BASE_V6_SCHEMA_PACKET.json; V6_MATCHING_SCHEMA_PACKET.json adds the two explicitly authorized actions without changing the V6 wire version. Request has exactly 35 unsigned fields; response exactly 16. Header and E5 messages use canonicalJSON; original HTTP body bytes are hashed without sorting, serialization, or whitespace replacement.

Suggested public port: `@ynx-chain/wallet-auth/product-session-task-action-v6`, Node-only with a browser rejection target and the matching declaration file. Parent alone installs that export and package/registry/version changes. This candidate does not change package.json. No public signer, provider setter, native getter, Root credential, storage writer, or network client is introduced.

Normal consumer sequence:

1. Capture actual method/path/body bytes and native identity from the original transport/session selection. Use `createProductSessionTaskActionBodyV6DATA` to obtain SHA256/length, then `assertProductSessionTaskActionBodyV6DATA(actualBody, unsigned)` to check exact route/action and the existing JSON operation body. Neither call approves the body.
2. Use `inspectProductSessionTaskActionHeaderV6Data(header, {networkId,unsigned,pkA,pkB})` with independently selected native/device current keys. Full ML-DSA-87 AND SLH-DSA-SHA2-256f mathematics, N1/index0/empty paths, original message and purpose are checked. Independently check registry, account/session/device current, policy/revocation, scopes, task holder, TaskGrant, user approval, egress/model/tool permissions, fresh clock and durable nonce/once state through their original owners.
3. Use `inspectProductSessionTaskResponseHeaderV6Data` with an independent actual Auth serverCurrent issuer and key pair. Response N1.owner is responseIssuer, never the user owner. `assertProductSessionTaskResponseBindingV6DATA` binds request signed-message E5 SHA256 (encodeProductSessionTaskActionV6Message bytes, excluding member and HTTP header), operationId, nonce, user/session/policy, actual status, independently retained requestRef and actual response body bytes. It produces only a state declaration. COMMITTED needs a nonempty opaque original record reference, which this codec does not prove exists. UNKNOWN never permits a new operation, nonce, or replay.

The actual task holder is the existing Go TaskRecord.Holder string. Creation requires holder=deviceId and null taskId/taskRevision/generation with a conversation creationBinding. Existing task holder/revision/generation must come from actual independently selected task state; equality of caller declarations is not qualification. requestRef is an original Auth same-SQLite once/request record string or null, not a synthesized operationId.

Nine mutation routes are registered by this matching profile; handoff remains explicitly unregistered until its actual implemented body contract arrives. task.propose-tool-step POST /api/tasks/{id}/tool-steps has exact body {operationId,taskRevision,generation,toolId,toolVersion,input}; its child operationId is a proposal reference, not the HTTP operationId or nonce. It proposes NEEDS_APPROVAL and grants no execution, disclosure or payment. task.complete POST /api/tasks/{id}/complete has exact {revision,generation,runId}; the signed runId must match. Original Auth same-SQLite logic must independently reject PENDING/SENT/UNKNOWN or unreconciled external steps. This codec never asserts workflow completion. Four GET reads and POST reconcile are query operations; reconcile does not authorize dispatch or a new effect nonce. The response requestDigest binds the currently signed query for reconcile. Any association with a previous effect must be established by the actual Auth durable Source/bridge, not inferred from a response header.

Run bodies require explicit resume boolean and toolIds array (empty allowed). Original Go ToolIDs is omitempty; the normal V6 producer must send an explicit array, or the owning contract must explicitly revise this unpublished profile. The helper does not silently fill missing fields or rewrite signed original bytes. JSON u64 numeric values are checked losslessly; unsigned metadata counters are canonical decimal strings.

PUBLIC golden has request/device and response/server public keys, original body, E5 messages, full N1 members and headers. Its temporary keys are generated only by tests and destroyed. It contains no operational Root/current qualification. All DATA outputs keep current/nativeAdmission/operationVerified/replayAuthorized false.

The standalone normal stdin DATA entry is `scripts/inspect-task-action-v6.mjs`: zero arguments; bounded canonical JSON stdin with request-data or response-data operation; stdout only on success, exit65 on invalid input. It never loads Native or touches Root/store/network. The test fixture and golden are tests only, excluded from production exports.

Matching regression entry: `node scripts/ci/task-action-v6-matching.mjs` at repository root. It runs only the matching action tests and matching strict declaration consumer; no old V4/V5 matrices or Native build. Parent adds the original workflow mapping and normal packed import validation.

Fixed response HTTP header: `x-ynx-product-session-response-proof-v6` (`PRODUCT_SESSION_TASK_RESPONSE_HEADER_V6`), independent of request header `x-ynx-product-session-proof-v6`. Request and response unsigned field counts remain 35/16. The signed-message requestDigest is neither bodyDigest nor SHA of the proof member/header. All new actions keep the same domains, certificate purposes, E5 framing, bounds and false-authority results. Generic proposal input is bounded original strict JSON syntax and is not a Catalog/tool schema approval; numerical lexemes are not rounded/re-serialized.
