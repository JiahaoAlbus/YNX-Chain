# Browser Product Session account-policy and reference reconciliation

`createBrowserProductSessionClient` accepts optional `accountPolicy: Readonly<PQClientAccountPolicyPorts>` from the existing Main same-realm protocol. Its exact `{acquire, verifyCompletion}` callable pair is checked and snapshotted before IndexedDB open or WebCrypto generation. Explicit undefined/null/bad shape rejects without device/store creation; omission retains existing behavior. `verifyCompletion` keeps the fixed `verifyPQProductSessionCompletionRecord` semantics and private opaque verification brand. Source ownership, recheck, retirement, drain, close and UNKNOWN debt remain in the original Recoverable client. No Source setter, approval bool, provider fallback or Node crypto import is added to the browser graph.

Direct V3 completion recovery now retains only a single private raw/opaque verification observation while the same original Source owner is held. Sole `deriveCompletionTarget` authenticates it; ordinary `inspectCompletionRecord(accountVerified:false)` does not. Before and after signing, original IDB bytes, same opaque observation, fresh clock/monotonic floor/expiry and target are checked. Only exact POST `/v2/product-sessions/introspect` and the canonical requiredScopes body digest can use this path while no active stored session exists. It never authorizes completion, business calls or a replacement session. Source retirement, changed raw, expiry, clock rollback or browser close refuses and clears the observation.

The normal browser reference branch does not need a browser account-policy port. Fixed FetchAdapter completeReturn/returnOutcome now retain one bounded immutable canonical sent triple plus the actual successfully parsed completed response. UNKNOWN and expired outcomes do not create a live entry. Package-private `borrowRetainedProductSessionReferenceReadTarget` reads only that actual adapter inventory; no setter or duck adapter can install it. It reuses sole signed reference inspection and `assertReferenceSession`, and holds only a local transport observation, never Root/Source/account permission. The same IDB original and loan identity/clock/expiry are checked pre/post-sign. Close releases only that loan and never closes a shared adapter. Active session storage and CONNECTED still occur only after fresh gateway introspection. Cold UNKNOWN completion uses original outcome; it never re-signs or resubmits device completion.

PUBLIC tests use Node WebCrypto, an explicit in-memory IndexedDB model, the actual HTTP kernel/FetchAdapter with fake fetch, and synthetic same-realm Source/registered public-key math. No genuine web Source, Root, ledger, real user account, network or Native admission is verified. Actual service policy/current/revocation and deployed browser caller remain Auth/P04/QA responsibilities. Root defaults and registered rows are not changed. This module does not touch rejected preproof-r3 actions.
