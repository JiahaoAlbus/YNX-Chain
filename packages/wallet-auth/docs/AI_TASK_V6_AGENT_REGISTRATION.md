# Independent AI Task V6 registration binding

The existing AI Source purpose/key, 14 operations, request 35 fields, response 16 fields, N1/frame and E5 bytes are unchanged. Client signed scope now requires `agentRegistration`; device-only profiles are rejected, not migrated. Server service issuer scope remains independent.

The closed registration expectation has exactly 15 fields: version (`1`), purpose (`PRODUCT-SESSION-AI-TASK-ACTION`), networkId, canonicalOwner, registrationId, registrationDigest, keyEpoch, pkA, pkB, sourceId, instanceId, resourceKey, protectedResourceRef, registeredAtMs, expiresAtMs. Keys are lowercase raw public-key hex (2592/64 bytes). keyEpoch is a positive canonical uint64 decimal string, independent of device revision. Source/instance/resourceKey must equal the stable current selector. Safe-integer Unix millisecond registration window must contain the profile window; no current-content hash or FD is pinned.

`registrationDigest` is SHA-256 of independently protected-read original registration record bytes. It is NOT a hash of this expectation object, profile, HTTP header, member or an object containing its own digest. The SDK checks digest shape and signed expected values; it neither defines a second protected record wire nor authenticates its origin. Auth must independently compare the actual protected record, original digest, public keys, epoch, registration ID, protected ref, selector and window, freshly check revocation/current and select the corresponding protected key.

`inspectOriginalAITaskActionV6SourceScopeDATA` returns read-only `agentPublic` expectation metadata alongside independent device/account DATA. Profile/current full AND mathematics expose it only after verification. Any agent pkA OR pkB reused from device HTTP, account asset/subject, Root, profile or current keys is rejected. Existing device registration/session/account-current, independent role signatures and profileDigest/current-head/window checks remain required. The returned metadata is not Root, Source, custody, registration, Native or permission authority.

The actual Native client `readOriginalScopeDATA()` exact shape is `{version,originURL,networkId,agentPublic,currentSelector,identity,expiresAtMs}`; no legacy top-level pkA/pkB. The client takes Task expected keys only from agentPublic, checks its network/owner/selector/window, and compares the entire freshly read scope against the retained original before/after effect stages. A replaced agent key/epoch/digest/ref or selector cannot reuse the original operation. Original member bytes and UNKNOWN remain retained on math refusal. Server response expected keys continue to come from independent actual server-current, never this client pair.

Auth Native/server producer and protected registration/current/key selection must consume this matching contract. Existing Native outputs are not silently upgraded. No actual registration, Root release, operational key issuance, Native admission, Hermes support or business activation is claimed by these PUBLIC tests. The Node-only DATA public port remains `@ynx-chain/wallet-auth/ai-native-task-action-v6-source-data`; no new public Source factory is introduced.
