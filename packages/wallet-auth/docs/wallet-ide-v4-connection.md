# Wallet/IDE V4 pair/completion/local association orchestration

Node-only Main entry: `@ynx-chain/wallet-auth/original-wallet-ide-v4-connection`.
Function: `openOriginalWalletIDEV4Connection()`; zero arguments, synchronous lifecycle owner. No callback, Source, provider, endpoint, key or dispatcher argument. Do not import it into renderer/browser/mobile. Existing `createProductWalletConnection` guard remains unchanged; this entry does not claim login completion.

Main integration order:
1. Retain this owner before calling any asynchronous method. `preparePair(independentSelection, {approvalOriginal,policyRef,abortContext})` uses the existing zero-argument registration client and Native pending Source. Selection bytes are captured before await; policyRef is the existing independently verified policy observation, not a boolean approval.
2. `readPreparedPair()` returns the exact original request DATA. Main must durably retain that body, original operation ID, account permission/current, approval and effect-entry marker in its existing protected outbox before explicitly calling `submitPair(SAMEabortContext)`. The SDK cannot attest Main persistence. No automatic POST or callback-based durability attestation is introduced.
3. Main retains Auth's original pair response/challenge. `prepareCompletion(independentSelectionWithChallengeOriginal, approvalInput)` first completes the previous client's close. A close failure retains debt and blocks the fresh zero-argument challenge-completion client. Identity/generation/public pair and canonical original challenge must match the prior flow. Completion request registrationOriginal/requestDigest are also bound to the original pair request. Read/persist the completion request before `submitCompletion(SAMEabortContext)`.
4. Retain original completion response. `finalizeOriginalAssociation(actualMainPeer,SAMEabortContext)` first drains completion. It adopts the unchanged finalization Source owner before interpreting error (only null succeeds). The existing identity DATA validator binds all twelve identity/application fields, generation and original pair operation ID against Native's review. Native alone recognizes the actual opaque Main peer; a DTO, cast or this comparison cannot establish its authority. The earlier creation operation is not supplied by the registration review contract; the original Native creation/registered-finalization peer must independently enforce that original creation, and no expected creation operation is invented here.
5. Permit recheck/commit/readOriginalOutcomeDATA use the same Native permit. A thrown commit also reads and retains the same permit's outcome before cleanup; UNKNOWN may have localAssociationFinalized=true and never authorizes replay. No outcome is promoted into connected/registered/newSession/Source.
6. Only an explicit successful local-association outcome allows `openSession(SAMEabortContext)`. This first drains finalization's child permit and Source, then independently acquires `acquireOriginalProductSessionDeviceV4ReadLeaseStage()`. Native current is held from its own Root/profile/current selection. Registered record decoding/digest reuses the sole SDK codec; identity/generation and session's registration tuple must match. Both original registration bytes and session UTF8 must equal the independently retained completion originals, with Native current pre/post checks. A mismatch retains the same stage for cleanup.
7. Returned held-session `assertCurrent()` and `readOriginalsDATA()` do not grant login or business access. `createBusinessProof()` precisely refuses `V4_CONNECTION_PROTECTED_STORE_CLOCK_NOT_SUPPLIED`: the read stage does not supply protected store namespace/revoke-marker or authority clock required by existing business-read constructor. Do not synthesize storage from a completion DTO or return a fake null revocation marker. IDE's separate existing R2 protected-store reader remains its own callee.
8. `restore()`/`revoke()` precisely refuse missing management Native producers. Existing Core HTTP V4 math may support other methods, but the GET Source grants no POST/DELETE management rights. Auth must supply separately reviewed exact operation/body/current/once management Sources. Main owns its caller changes; this overlay does not alter Main.

The SAME frozen abort context/SAME AbortSignal is required throughout. Main owns cancellation; this module does not replace/abort a caller signal. `retire()` prevents new entries, then `close()` drains flights and actual resources in child-before-parent order. Pending join never selects close or parent. Later close may drain the original debt, without new acquisition or business retry. Original first cause, including false/null/undefined, is retained. Original HTTP member/response and Native finalization outcomes survive late errors. Returned DATA is isolated from the retained cross-phase originals.

Production Root/release/current/keys, installed matching Native image, TLS/HTTP runtime, real login/session restoration/revocation remain unverified. PUBLIC controls and Source/math imports never confer Root/Source/Native/business admission. No account/database/key/network/GUI operation is performed by the controls.
