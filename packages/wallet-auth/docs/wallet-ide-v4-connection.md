# Wallet/IDE V4 per-phase cleanup and normal business-read

Node-only entry stays `@ynx-chain/wallet-auth/original-wallet-ide-v4-connection`; no browser/mobile/provider export is added. `openOriginalWalletIDEV4Connection()` owns the whole journey, not an already-connected session.

Main adapter sequence:
- Pair: create frozen original ctx1; reviewPair(selection,ctx1) -> actual protected approval -> preparePair(selection,approvalInput with SAME ctx1) -> protected original request/effect-entry persistence -> submitPair(ctx1). In Main/controller finally call closePairPhase(), inspect statusDATA().pairPhase, then abort ctx1. Closing pair does not retire the journey.
- Completion: only after pairPhase.closed && cleanupComplete && !cleanupDebt and retained original pair response, create independent frozen ctx2; reviewCompletion(independentSelectionWithOriginalChallenge,ctx2) -> its actual protected approval -> prepareCompletion with SAME ctx2 -> actual protected persistence -> submitCompletion(ctx2). Finally closeCompletionPhase(), inspect completionPhase, then abort ctx2. Prior-phase approval is never inherited.
- Finalization: only after actual completion drain, create independent ctx3. reviewFinalization(ctx3) acquires ONE original finalization Source/review. Main creates its actual Native-recognized private peer using this SAME review. finalizeOriginalAssociation(peer,ctx3) uses the SAME Source. Finally closeFinalizationPhase(), inspect finalizationPhase, then abort ctx3. Only null acquisition error succeeds; false/0/undefined errors and actual partials retain exact custody.
- Held session: confirmed original local-association outcome plus physical finalization drain permits openSession(new independent ctx4). It separately acquires the existing ReadLeaseStage; current and original session/registration bytes remain independently checked. It cannot manufacture a session from a DATA outcome.

Each phase status is exactly the lifecycle DATA {closed,cleanupDebt,cleanupComplete,firstCausePresent,firstCause}. closed/cleanupComplete become true only after actual phase resource drain, including all active flights; debt/falsy errors are not coerced. A close failure blocks the next Source, and later drain uses the same original owner. closePairPhase/closeCompletionPhase/closeFinalizationPhase never retire the journey. Whole journey retire()/close() remain for terminal shutdown. No blind reacquisition or business resubmission is added.

Normal business read is now implemented, not a missing-clock placeholder: after openSession, call journey.openBusinessRead (or held.openBusinessRead) with exact Main configuration {registry,productId,platform,storage,gatewayTimeoutMs}. storage is the original Main protected safeStorage capability including its actual session and revoke marker; it is not a fake Source or manufactured in-memory session. SDK injects the SAME actual lease.device/deviceCurrent and held ctx4, and calls existing ./product-wallet-connection-node.js::createProductWalletBusinessReadClient. The existing normal FetchAdapter owns fixed HTTPS authority-time GET and verified response parsing, not PrivateAdapter/window/Date.now fallback. No caller clock/fetch/provider/Source/endpoint is accepted. The reader owns normal existing-session GET proof only, never management POST/DELETE. Calling held.createBusinessProof without selecting that normal configuration precisely refuses BUSINESS_READ_CONFIGURATION_REQUIRED.

Business child is adopted before late current/retire checks, including thrown partial. close drains child before held parent; a child close failure retains parent debt and exact first cause. A late child after journey retirement is retained and drained, not discarded or replaced. Business read does not expose internal Native stage, current provider or signing API. Root/Source/Native/connected/newSession flags remain false.

Review binding, immutable originals, twelve-field independent identity, original pair operation, same-owner approval, partial Native permit, original UNKNOWN/local effect/readback and raw HTTP member/response controls remain. The previous 18 review controls are retained with required per-phase context/cleanup adaptations, plus 11 lifecycle/business controls. Initial fixture reds (global previous ctx, then a wrong fixture-owner assertion) are preserved; no production grant/current guard is weakened. The actual factory control executes original session parsing/storage reads and one normal authority-time GET against PUBLIC transport bytes, then refuses missing PUBLIC Native proof. It does not sign or send a real request.

restore/revoke management Source/Native producers remain NOT_SUPPLIED. Old createProductWalletConnection guard is unchanged. Main/P03 actual caller adaptation, installed matching image, protected Root/release/current/keys/TLS and real login/restore/revoke validation remain separate. No Native build, GUI, actual account/database/key/network or shared product source writes occur in this overlay.
