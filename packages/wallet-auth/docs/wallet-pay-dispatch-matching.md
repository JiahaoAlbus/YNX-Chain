# Wallet client SourceV2 dispatch policy matching

The existing sole verifier already accepts exact eight-field policy for `wallet-native-pay-client-source-v1`: rootDigest, enrollmentDigest, endpoint, spki, signatureContract, applicationId, productId, platform. It independently requires productId wallet and the existing admitted release platform/application identity. The actual normal `original-auth-source-v2-dispatch.mjs` omitted this purpose from that branch and applied its legacy five-field schema. Consequently normal `auth-source-v2-native-node/v1` stdin rejected the legitimate client policy before Root/current checks.

Production delta is only the existing WPC purpose constant import and the matching closed-purpose eight-field branch. The original generic signature/registered-role AND/profile/current/head/expiry mathematics, raw bytes, domains and Source contracts are unchanged. No field is made optional; old unrelated purposes keep their exact schemas. No new domain, codec, permission, Source, Native getter or approval is created. Wallet actual Native startup handle/Root loader port remains independently pending.

The new test suite executes both actual dispatch and the original bounded stdin CLI. Root0 policy bytes pin failure remains AUTH_SOURCE_V2_NOT_PINNED before any I/O; extra approved/platform/policy fields under other purposes are rejected. Old IDE five-field policy still reaches that same pin boundary, and an added platform is rejected. PUBLIC registered role ML-DSA+SLH fixtures execute profile and fresh nonce-current verification with before/after registration captures. Same sequence wrong head correctly reports AUTH_SOURCE_V2_EQUIVOCATION before WPC's head check; next sequence wrong head reports WALLET_PAY_CLIENT_SOURCE_CURRENT_HEAD. Cross-purpose signed Root remains AUTH_SOURCE_V2_ROOT.

The positive original CLI test has a test-host-only `--import` preload that supplies an HTTPS EventEmitter double. It does not modify stdin/CLI production bytes or accept a provider field. The child itself creates PUBLIC temporary role keys, sends only public canonical input over test IPC, handles its original random current nonce with the existing signer fixture, and destroys keys at exit. Exactly eight registration reads and one fresh current fetch run through the original transport call sites. There is no real TLS/server/chain/Source registration or authority in this test. The preload is only test source, not a production API or normal package entry.

Commands: `node packages/wallet-auth/scripts/ci/wallet-pay-dispatch-matching.mjs` (new suite only, normal dependencies installed); or `node --test packages/wallet-auth/test/wallet-pay-dispatch-matching.test.mjs`. No old Wallet/Native math or business matrix was rerun. The local first broad run passed four new groups and exposed two fixture/expectation failures; only failed cases were rerun, then the new legacy compatibility group. First failures are preserved in task evidence. Hosted CI can run the complete new seven-group suite once after integration.
